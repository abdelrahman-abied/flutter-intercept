# Contracts

Every package codes against these. Only the lead changes this file; if you need a change,
put it under "Requested contract changes" in your `docs/spikes/<agent>.md` and work around it.

## 1. Generated Dart entry point

Path: `<flutterProjectRoot>/.dart_tool/flutter_intercept/entry_<name>.dart`. `<name>` is the target's
full project-relative path without `.dart`, `/` → `__` (`lib/main.dart` → `entry_lib__main.dart`,
`lib/flavors/dev/main.dart` → `entry_lib__flavors__dev__main.dart`, `bin/main.dart` → `entry_bin__main.dart`).
When that mapping is lossy (a character outside `[A-Za-z0-9_]` replaced, or `__` already in a segment) or
the target is outside the project root, `_<first 8 hex of sha1(path)>` is appended. Overwritten every session.
The **content is device independent** (same bytes for an emulator and a simulator session).
Uses **dart:io, dart:async and dart:convert only** — never adds a dependency to the app.

Template v6 (placeholders in `{{ }}`) — v5 plus the gRPC `Socket.connect` hook (§16.1, docs/spikes/template-v6.md); v5 = v4 plus `flutterInterceptInstall()` for background isolates (§13.3,
docs/spikes/background-isolates.md); v4 = v3 plus request → source (§9.1), validated on Android emulator + iOS
simulator and Dart SDKs 3.0–3.13 (docs/spikes/template-v4.md; v3: docs/spikes/template-v3.md). It **trusts** this
install's CA (below) instead of accepting any certificate:
proxy leaf certificates pass normal chain + hostname verification; the `; DIRECT` fallback is verified exactly
as without Flutter Intercept. The returned client is a wrapper that ignores app assignments to `findProxy`;
`badCertificateCallback` is the app's own (forwarded):

```dart
// GENERATED by Flutter Intercept. Do not edit. Safe to delete.
import 'dart:async';
import 'dart:convert';
import 'dart:io';
import 'dart:math';
import '{{TARGET_IMPORT}}' as target; // package:<app>/<path> when under lib/, else relative

// Flutter sessions pass --dart-define=FLUTTER_INTERCEPT_PROXY=<host:port> (device dependent);
// the default serves plain Dart sessions, which run on the host and take no dart-define.
const _proxyAddress = String.fromEnvironment('FLUTTER_INTERCEPT_PROXY', defaultValue: 'localhost:{{PROXY_PORT}}');
const _proxy = 'PROXY $_proxyAddress; DIRECT';

String _findProxy(Uri url) => _proxy;

// Request -> source (CONTRACTS §9.1). Each request carries an opaque `x-fi-id` header; the stack
// captured when the app opened it goes to the proxy out of band (never upstream). Flutter sessions
// pass --dart-define=FLUTTER_INTERCEPT_TRACE=0 when the user turned it off.
const _traceEnabled = String.fromEnvironment('FLUTTER_INTERCEPT_TRACE') != '0';
// Libraries such as Dio open the connection several async hops after the app's call, so the stack at
// that point no longer shows it. In debug (JIT) sessions the app runs in a zone that remembers where
// each callback was registered (like package:stack_trace's Chain.capture); never in profile builds.
const _traceChains = _traceEnabled && !bool.fromEnvironment('dart.vm.profile') && !bool.fromEnvironment('dart.vm.product');
const _traceHeader = 'x-fi-id';
// `.invalid` never resolves and the side channel has no `; DIRECT`: stacks only ever reach the proxy.
final Uri _traceUrl = Uri.parse('https://trace.flutter-intercept.invalid/v1/traces');
const _traceMaxChars = 16000;
const _traceBatch = 50;
const _traceQueueLimit = 1000;
// Flutter apps keep the side channel's connection for the next batch; plain Dart programs close it.
const _flutterApp = bool.fromEnvironment('dart.library.ui');

// Random per isolate start (so ids stay unique across hot restarts) + a counter.
final String _tracePrefix = () {
  Random random;
  try {
    random = Random.secure();
  } catch (_) {
    random = Random(DateTime.now().microsecondsSinceEpoch);
  }
  final buffer = StringBuffer();
  for (var i = 0; i < 16; i++) {
    buffer.write(random.nextInt(16).toRadixString(16));
  }
  return buffer.toString();
}();
int _traceCount = 0;

class _PendingTrace {
  _PendingTrace(this.id, this.stack, this.chain);
  final String id;
  final StackTrace stack;
  final List<StackTrace>? chain;

  /// The VM stack, then (whole) earlier registrations in package:stack_trace's Chain format.
  String format() {
    var out = _lean('$stack');
    final c = chain;
    if (c != null) {
      for (final t in c) {
        final segment = _lean('$t');
        if (segment.isEmpty) continue;
        final next = '$out$_chainGap\n$segment';
        if (next.length > _traceMaxChars) break;
        out = next;
      }
    }
    return out.length > _traceMaxChars ? out.substring(0, _traceMaxChars) : out;
  }
}

/// VM stack lines without frames of `dart:` libraries and of this file (event loop and zone
/// plumbing, never the app's call site); `<asynchronous suspension>` markers between kept frames stay.
String _lean(String trace) {
  final out = StringBuffer();
  var suspended = false;
  for (final line in trace.split('\n')) {
    if (line.isEmpty) continue;
    if (line == '<asynchronous suspension>') {
      suspended = true;
      continue;
    }
    if (line.contains('(dart:') || (line.contains('/.dart_tool/') && line.contains('/entry_'))) continue;
    if (suspended && out.isNotEmpty) out.write('<asynchronous suspension>\n');
    suspended = false;
    out.write('$line\n');
  }
  return out.toString();
}

const _chainDepth = 10;
const _chainGap = '===== asynchronous gap ===========================';
// Registration stacks of the callback running now, newest first (null outside the chain zone).
List<StackTrace>? _currentChain;

List<StackTrace> _chainHere() {
  final parent = _currentChain;
  final out = <StackTrace>[StackTrace.current];
  if (parent != null) {
    for (var i = 0; i < parent.length && out.length < _chainDepth; i++) {
      out.add(parent[i]);
    }
  }
  return out;
}

// Microtasks and timers keep the chain they were scheduled under without a capture of their own: they
// are scheduled at least once per `await`, which would double the cost, and the code that schedules
// one from the app's call already registered a `then` (captured below) or runs the app's own closure.
ZoneCallback<R> _registerCallback<R>(Zone self, ZoneDelegate parent, Zone zone, R Function() f) {
  final chain = _currentChain;
  final g = parent.registerCallback<R>(zone, f);
  if (chain == null) return g;
  return () {
    final previous = _currentChain;
    _currentChain = chain;
    try {
      return g();
    } finally {
      _currentChain = previous;
    }
  };
}

ZoneUnaryCallback<R, T> _registerUnaryCallback<R, T>(Zone self, ZoneDelegate parent, Zone zone, R Function(T) f) {
  final chain = _chainHere();
  final g = parent.registerUnaryCallback<R, T>(zone, f);
  return (T a) {
    final previous = _currentChain;
    _currentChain = chain;
    try {
      return g(a);
    } finally {
      _currentChain = previous;
    }
  };
}

// Error handlers keep the chain they were registered under without a capture of their own (half the
// cost of an `await`); a retry from an error handler still leads back to the app's call.
ZoneBinaryCallback<R, T1, T2> _registerBinaryCallback<R, T1, T2>(
    Zone self, ZoneDelegate parent, Zone zone, R Function(T1, T2) f) {
  final chain = _currentChain;
  final g = parent.registerBinaryCallback<R, T1, T2>(zone, f);
  if (chain == null) return g;
  return (T1 a, T2 b) {
    final previous = _currentChain;
    _currentChain = chain;
    try {
      return g(a, b);
    } finally {
      _currentChain = previous;
    }
  };
}

final List<_PendingTrace> _pendingTraces = <_PendingTrace>[];
Timer? _traceTimer;
int _tracePosts = 0;
HttpClient? _traceClient;
bool _traceFailed = false;

/// Tags a request the app is opening with an id and queues the app's stack for the proxy.
/// Must be called synchronously from the HttpClient member the app called.
Future<HttpClientRequest> _traced(Future<HttpClientRequest> request) {
  if (!_traceEnabled) return request;
  final stack = StackTrace.current;
  _traceCount++;
  final id = '$_tracePrefix-${_traceCount.toRadixString(36)}';
  if (_pendingTraces.length >= _traceQueueLimit) _pendingTraces.removeAt(0);
  _pendingTraces.add(_PendingTrace(id, stack, _currentChain));
  _traceTimer ??= Zone.root.createTimer(const Duration(milliseconds: 100), _flushTraces);
  return request.then((HttpClientRequest r) {
    try {
      r.headers.set(_traceHeader, id);
    } catch (_) {
      // Headers already sent or immutable: this request just has no source.
    }
    return r;
  });
}

void _flushTraces() {
  _traceTimer = null;
  while (_pendingTraces.isNotEmpty) {
    final n = _pendingTraces.length < _traceBatch ? _pendingTraces.length : _traceBatch;
    final batch = _pendingTraces.sublist(0, n);
    _pendingTraces.removeRange(0, n);
    _postTraces(batch);
  }
}

class _UntracedOverrides extends HttpOverrides {}

Future<void> _postTraces(List<_PendingTrace> batch) async {
  _tracePosts++;
  try {
    // A plain dart:io client (not the app's, not wrapped, never traced) that may only use the proxy, over
    // one connection so batches never compete with the app for the proxy's per-client connection budget.
    final client = _traceClient ??=
        HttpOverrides.runWithHttpOverrides<HttpClient>(() => HttpClient(), _UntracedOverrides())
          ..findProxy = ((Uri url) => 'PROXY $_proxyAddress')
          ..maxConnectionsPerHost = 1;
    final traces = <Map<String, String>>[];
    for (final t in batch) {
      traces.add(<String, String>{'id': t.id, 'stack': t.format()});
    }
    final body = utf8.encode(jsonEncode(<String, Object>{'traces': traces}));
    final request = await client.postUrl(_traceUrl);
    request.headers.contentType = ContentType.json;
    request.contentLength = body.length;
    request.add(body);
    final response = await request.close();
    await response.drain<void>();
  } catch (e) {
    if (!_traceFailed) {
      _traceFailed = true;
      _note('request sources are unavailable (could not reach the intercept proxy: $e)');
    }
  } finally {
    _tracePosts--;
    // An idle keep-alive connection would hold a plain Dart program open for 15 s.
    if (!_flutterApp && _tracePosts == 0 && _pendingTraces.isEmpty && _traceTimer == null) {
      _traceClient?.close();
      _traceClient = null;
    }
  }
}

// Certificate of this machine's Flutter Intercept CA (its private key never leaves the
// development machine). It is *trusted* in addition to the normal roots, so the proxy's
// per-host certificates pass ordinary chain + hostname verification, and DIRECT traffic
// (proxy unreachable) is verified exactly as without Flutter Intercept.
const _caCertificate = r'''
{{CA_CERT_PEM}}''';

final Expando<bool> _trustedContexts = Expando<bool>();
void _trustCa(SecurityContext context) {
  if (_trustedContexts[context] == true) return;
  _trustedContexts[context] = true;
  try {
    context.setTrustedCertificatesBytes(utf8.encode(_caCertificate));
  } catch (e) {
    // Already present (e.g. CERT_ALREADY_IN_HASH_TABLE) is fine. Otherwise interception of
    // this context's HTTPS fails closed: the TLS handshake fails and Dart falls back to DIRECT.
    if (!'$e'.contains('ALREADY')) _note('could not trust the Flutter Intercept CA: $e');
  }
}

final Set<String> _noted = <String>{};
void _note(String message) {
  if (_noted.add(message)) print('[flutter_intercept] $message');
}

class _FlutterInterceptOverrides extends HttpOverrides {
  _FlutterInterceptOverrides(this._previous);
  final HttpOverrides? _previous;
  bool _creating = false;

  @override
  HttpClient createHttpClient(SecurityContext? context) {
    // Re-entered from a delegate that calls HttpClient() itself: give it a
    // plain client; the outer call configures and wraps it.
    if (_creating) return super.createHttpClient(context);
    _trustCa(context ?? SecurityContext.defaultContext);
    // Our zone value shadows any HttpOverrides.global the app installs later;
    // delegate to it so the app's own overrides still apply underneath ours.
    final global = Zone.root.run(() => HttpOverrides.current);
    final delegate = (global != null && !identical(global, this)) ? global : _previous;
    HttpClient client;
    if (delegate != null) {
      _creating = true;
      try {
        client = delegate.createHttpClient(context);
      } finally {
        _creating = false;
      }
    } else {
      client = super.createHttpClient(context);
    }
    if (client is _InterceptedHttpClient) return client;
    client.findProxy = _findProxy;
    return _InterceptedHttpClient(client);
  }
}

/// Forwards every member to the real client, except that app assignments to
/// `findProxy` made after creation (Charles-style snippets,
/// findProxyFromEnvironment) are ignored so traffic stays on the proxy.
/// `badCertificateCallback` is the app's own (forwarded): it is never consulted
/// for proxy certificates, which are trusted, and keeps its meaning on DIRECT.
/// Callback setters take `dynamic` so their exact function types can never
/// mismatch the SDK; members added by future SDKs reach `noSuchMethod`.
class _InterceptedHttpClient implements HttpClient {
  _InterceptedHttpClient(this._client);
  final HttpClient _client;

  @override
  set findProxy(dynamic f) {
    if (f != null) _note('ignored app findProxy (requests stay on the intercept proxy)');
  }

  @override
  set badCertificateCallback(dynamic callback) => _client.badCertificateCallback = callback;

  @override
  set connectionFactory(dynamic f) {
    if (f != null) _note('app set connectionFactory: its connections may bypass the intercept proxy');
    _client.connectionFactory = f;
  }

  @override
  Duration get idleTimeout => _client.idleTimeout;
  @override
  set idleTimeout(Duration value) => _client.idleTimeout = value;
  @override
  Duration? get connectionTimeout => _client.connectionTimeout;
  @override
  set connectionTimeout(Duration? value) => _client.connectionTimeout = value;
  @override
  int? get maxConnectionsPerHost => _client.maxConnectionsPerHost;
  @override
  set maxConnectionsPerHost(int? value) => _client.maxConnectionsPerHost = value;
  @override
  bool get autoUncompress => _client.autoUncompress;
  @override
  set autoUncompress(bool value) => _client.autoUncompress = value;
  @override
  String? get userAgent => _client.userAgent;
  @override
  set userAgent(String? value) => _client.userAgent = value;

  @override
  Future<HttpClientRequest> open(String method, String host, int port, String path) =>
      _traced(_client.open(method, host, port, path));
  @override
  Future<HttpClientRequest> openUrl(String method, Uri url) => _traced(_client.openUrl(method, url));
  @override
  Future<HttpClientRequest> get(String host, int port, String path) => _traced(_client.get(host, port, path));
  @override
  Future<HttpClientRequest> getUrl(Uri url) => _traced(_client.getUrl(url));
  @override
  Future<HttpClientRequest> post(String host, int port, String path) => _traced(_client.post(host, port, path));
  @override
  Future<HttpClientRequest> postUrl(Uri url) => _traced(_client.postUrl(url));
  @override
  Future<HttpClientRequest> put(String host, int port, String path) => _traced(_client.put(host, port, path));
  @override
  Future<HttpClientRequest> putUrl(Uri url) => _traced(_client.putUrl(url));
  @override
  Future<HttpClientRequest> delete(String host, int port, String path) =>
      _traced(_client.delete(host, port, path));
  @override
  Future<HttpClientRequest> deleteUrl(Uri url) => _traced(_client.deleteUrl(url));
  @override
  Future<HttpClientRequest> patch(String host, int port, String path) =>
      _traced(_client.patch(host, port, path));
  @override
  Future<HttpClientRequest> patchUrl(Uri url) => _traced(_client.patchUrl(url));
  @override
  Future<HttpClientRequest> head(String host, int port, String path) => _traced(_client.head(host, port, path));
  @override
  Future<HttpClientRequest> headUrl(Uri url) => _traced(_client.headUrl(url));

  @override
  set authenticate(dynamic f) => _client.authenticate = f;
  @override
  void addCredentials(Uri url, String realm, HttpClientCredentials credentials) =>
      _client.addCredentials(url, realm, credentials);
  @override
  set authenticateProxy(dynamic f) => _client.authenticateProxy = f;
  @override
  void addProxyCredentials(String host, int port, String realm, HttpClientCredentials credentials) =>
      _client.addProxyCredentials(host, port, realm, credentials);
  @override
  set keyLog(dynamic callback) => _client.keyLog = callback;
  @override
  void close({bool force = false}) => _client.close(force: force);

  // Only reached for HttpClient members added by a future SDK (all members of
  // Dart 3.0-3.13 are forwarded above). Setters are dropped (the app keeps
  // working with the SDK default); getters/methods cannot be forwarded.
  @override
  dynamic noSuchMethod(Invocation invocation) {
    _note('HttpClient member ${invocation.memberName} is not supported by this Flutter Intercept version'
        '${invocation.isSetter ? ' (assignment ignored)' : ''}');
    if (invocation.isSetter) return null;
    return super.noSuchMethod(invocation);
  }
}

// gRPC (CONTRACTS §16.1). grpc-dart, and connectrpc's HTTP/2 transport, open their connection with a plain
// Socket.connect, which HttpOverrides never sees. Those connects (recognised by the library's frame on the
// stack) go to the proxy instead, through a "silent" CONNECT: the proxy never answers it and relays or decodes
// what follows. Every other connect goes direct, exactly as without Flutter Intercept. Off with
// --dart-define=FLUTTER_INTERCEPT_GRPC=0 and in sessions without the proxy define (plain Dart).
const _grpcEnabled =
    String.fromEnvironment('FLUTTER_INTERCEPT_GRPC') != '0' && bool.hasEnvironment('FLUTTER_INTERCEPT_PROXY');
const _grpcFrames = <String>[
  'package:grpc/src/client/http2_connection.dart',
  'package:connectrpc/src/http2/connection.dart',
];
// Connecting to the proxy takes at most 2 s (or the app's connectTimeout if shorter), then the call goes direct.
const _grpcHopTimeout = Duration(seconds: 2);
// grpc-dart reconnects at once when an accepted connection drops: after 3 tunnels to one authority within
// 2 s, that authority goes direct for 30 s (per isolate).
const _grpcBurstTunnels = 3;
const _grpcBurstMs = 2000;
const _grpcDirectMs = 30000;

// IOOverrides.global before ours: direct connects go through it (null: the SDK's own).
IOOverrides? _ioPrevious;
// A scope that overrides nothing: the SDK's own behaviour, for the hop to the proxy.
IOOverrides? _ioPlain;
final Map<String, List<int>> _grpcTunnels = <String, List<int>>{};
final Map<String, int> _grpcDirectUntil = <String, int>{};

// Not a subclass (IOOverrides is `abstract base`, and a `base`/`final` subclass does not parse in apps on a
// pre-3.0 language version): a scope from IOOverrides.runZoned is a ready-made IOOverrides. Installed as the
// global only, never in a zone, so that an IOOverrides.global the app sets later still takes effect.
void _installIO() {
  if (!_grpcEnabled) return;
  final previous = Zone.root.run(() => IOOverrides.current);
  try {
    IOOverrides.global = null;
    _ioPlain = Zone.root.run(() => IOOverrides.runZoned(() => IOOverrides.current!));
    IOOverrides.global = previous;
    final ours = Zone.root.run(() => IOOverrides.runZoned(() => IOOverrides.current!, socketConnect: _grpcConnect));
    _ioPrevious = previous;
    IOOverrides.global = ours;
  } catch (e) {
    IOOverrides.global = previous;
    _note('gRPC calls are not intercepted ($e)');
  }
}

Future<Socket> _grpcConnect(dynamic host, int port, {dynamic sourceAddress, int sourcePort = 0, Duration? timeout}) {
  final unix = host is InternetAddress && host.type == InternetAddressType.unix;
  if (unix || !_grpcCaller()) return _grpcDirect(host, port, sourceAddress, sourcePort, timeout);
  return _grpcTunnel(host, port, sourceAddress, sourcePort, timeout);
}

bool _grpcCaller() {
  final stack = StackTrace.current.toString();
  for (final frame in _grpcFrames) {
    if (stack.contains(frame)) return true;
  }
  return false;
}

Future<Socket> _grpcDirect(dynamic host, int port, dynamic sourceAddress, int sourcePort, Duration? timeout) {
  return IOOverrides.runWithIOOverrides(
      () => Socket.connect(host, port, sourceAddress: sourceAddress, sourcePort: sourcePort, timeout: timeout),
      _ioPrevious ?? _ioPlain!);
}

// FLUTTER_INTERCEPT_PROXY is [user:token@]host:port (the host may be an [IPv6] literal).
String _grpcProxyHost() {
  final hostPort = _proxyAddress.substring(_proxyAddress.indexOf('@') + 1);
  final host = hostPort.substring(0, hostPort.lastIndexOf(':'));
  return host.startsWith('[') && host.endsWith(']') ? host.substring(1, host.length - 1) : host;
}

int _grpcProxyPort() => int.parse(_proxyAddress.substring(_proxyAddress.lastIndexOf(':') + 1));

String _grpcProxyAuthorization() {
  final at = _proxyAddress.indexOf('@');
  if (at < 0) return '';
  return 'Proxy-Authorization: Basic ${base64Encode(utf8.encode(_proxyAddress.substring(0, at)))}\r\n';
}

// Tells the proxy that the breaker sent this authority direct (CONTRACTS §16.8): one more connection that carries
// only a `breaker` head, then is closed. Best effort: never awaited by the app's connect, errors swallowed.
void _grpcBreakerReport(String authority) {
  Zone.root.run(() {
    try {
      final head = 'CONNECT $authority HTTP/1.1\r\n'
          'Host: $authority\r\n'
          'Flutter-Intercept-Tunnel: breaker\r\n'
          '${_grpcProxyAuthorization()}'
          '\r\n';
      final proxyHost = _grpcProxyHost();
      final proxyPort = _grpcProxyPort();
      IOOverrides.runWithIOOverrides(
              () => Socket.connect(proxyHost, proxyPort, timeout: _grpcHopTimeout), _ioPlain!)
          .then((Socket socket) {
        socket.done.then((Object? v) => null, onError: (Object e) => null);
        socket.add(utf8.encode(head));
        return socket.flush().whenComplete(socket.destroy);
      }).then((Object? v) => null, onError: (Object e) => null);
    } catch (_) {
      // Malformed proxy define: nothing to report to.
    }
  });
}

Future<Socket> _grpcTunnel(dynamic host, int port, dynamic sourceAddress, int sourcePort, Duration? timeout) async {
  final target = host is InternetAddress ? host.address : '$host';
  final authority = target.contains(':') && !target.startsWith('[') ? '[$target]:$port' : '$target:$port';
  final now = DateTime.now().millisecondsSinceEpoch;
  if ((_grpcDirectUntil[authority] ?? 0) > now) return _grpcDirect(host, port, sourceAddress, sourcePort, timeout);
  final recent = _grpcTunnels.putIfAbsent(authority, () => <int>[]);
  recent.removeWhere((int t) => now - t >= _grpcBurstMs);
  if (recent.length >= _grpcBurstTunnels) {
    recent.clear();
    _grpcDirectUntil[authority] = now + _grpcDirectMs;
    _note("gRPC connections to $authority kept closing, so the app connects directly for 30 s — Flutter Intercept "
        "rules and network simulation don't apply to them meanwhile.");
    _grpcBreakerReport(authority);
    return _grpcDirect(host, port, sourceAddress, sourcePort, timeout);
  }
  final hop = timeout != null && timeout < _grpcHopTimeout ? timeout : _grpcHopTimeout;
  final watch = Stopwatch()..start();
  Socket socket;
  String head;
  try {
    final proxyHost = _grpcProxyHost();
    final proxyPort = _grpcProxyPort();
    final authorization = _grpcProxyAuthorization();
    socket = await IOOverrides.runWithIOOverrides(
        () => Socket.connect(proxyHost, proxyPort, timeout: hop), _ioPlain!);
    final left = timeout == null ? null : timeout - watch.elapsed;
    final ms = left == null ? null : (left.inMilliseconds < 1 ? 1 : left.inMilliseconds);
    head = 'CONNECT $authority HTTP/1.1\r\n'
        'Host: $authority\r\n'
        'Flutter-Intercept-Tunnel: silent\r\n'
        '${ms == null ? '' : 'Flutter-Intercept-Connect-Timeout: $ms\r\n'}'
        '$authorization'
        '\r\n';
  } catch (_) {
    // Proxy unreachable: connect direct with what is left of the app's timeout.
    final left = timeout == null ? null : timeout - watch.elapsed;
    if (left != null && left <= Duration.zero) rethrow;
    return _grpcDirect(host, port, sourceAddress, sourcePort, left);
  }
  recent.add(now);
  // No reply is ever read: the app's HTTP/2 (h2c or TLS) follows the head on the same connection.
  socket.add(utf8.encode(head));
  return socket;
}

// Statics, and so HttpOverrides.global, are per isolate. In debug sessions Flutter Intercept calls
// flutterInterceptInstall through the VM service in every new isolate of the app (compute,
// Isolate.run, Isolate.spawn) while it is paused at start, before any of its code runs (CONTRACTS
// §13.3). The main isolate installs from main below; a second call is a no-op.
_FlutterInterceptOverrides? _installed;

_FlutterInterceptOverrides _install() {
  final existing = _installed;
  if (existing != null) return existing;
  _trustCa(SecurityContext.defaultContext);
  final overrides = _FlutterInterceptOverrides(HttpOverrides.current);
  HttpOverrides.global = overrides;
  _installIO();
  return _installed = overrides;
}

@pragma('vm:entry-point')
void flutterInterceptInstall() {
  _install();
}

Future<void> main(List<String> args) async {
  final overrides = _install();
  // Zone value wins over a later `HttpOverrides.global = ...` inside the app.
  await HttpOverrides.runWithHttpOverrides(() {
    if (!_traceChains) return _runTarget(args);
    return runZoned(() => _runTarget(args),
        zoneSpecification: ZoneSpecification(
            registerCallback: _registerCallback,
            registerUnaryCallback: _registerUnaryCallback,
            registerBinaryCallback: _registerBinaryCallback));
  }, overrides);
}

Future<void> _runTarget(List<String> args) async {
  // Works for `void main()`, `Future<void> main() async` and `main(List<String>)`.
  final dynamic entry = target.main;
  final dynamic result = entry is Function(List<String>) ? entry(args) : entry();
  if (result is Future) await result;
}
```

Rules for the generator:
- Fills `TARGET_IMPORT`, `PROXY_PORT` (default address `localhost:<port>`, used by plain-Dart sessions)
  and `CA_CERT_PEM` (exactly one PEM `CERTIFICATE` block of the install CA — never a key). No
  main-signature detection needed. Never write an entry whose CA placeholder is unfilled.
- The entry inherits the app's language version: no `_` wildcards (Dart ≥3.7) or records.
- **Every Flutter session (not plain Dart — the Dart VM aborts on `--dart-define`) the provider appends
  `--dart-define=FLUTTER_INTERCEPT_ENTRY_SHA=<first 12 hex of sha1(entry bytes)>` and
  `--dart-define=FLUTTER_INTERCEPT_PROXY=<PROXY_HOST>:<port>` (§2) to `toolArgs`**, replacing any earlier
  copies. flutter_tools excludes `.dart_tool` paths from Gradle's inputs, so without the SHA define Android
  can bundle a stale entry when only its contents changed (measured); dart-defines are Gradle inputs.

Per-install CA (extension, `src/ca.ts`):
- Generated once on the first intercepted launch (mockttp's `generateCACertificate`, RSA 2048, random
  subject `CN=Flutter Intercept CA <16 hex>`, `O=Flutter Intercept (local development only)`), stored as
  `<context.globalStorageUri>/flutter-intercept-ca.json` (`{key, cert}` PEM), file mode **0600**, dir 0700;
  created atomically (concurrent windows converge on one CA). Regenerated when unreadable, not a CA, key ≠
  cert, or expiring within 30 days.
- The same CA is passed to `InterceptProxy({ ca })` on every start and its certificate is embedded in
  every entry. The private key never leaves the development machine.
- Apps that reject the proxy certificate anyway (another CA, Dio `validateCertificate`, a delegate that
  builds its own `SecurityContext`) fail closed: the TLS handshake to the proxy fails and Dart falls back to
  verified DIRECT.

Agent A validates this template on devices; Agent B owns the generator. If A finds the
template wrong, A reports and the lead updates it here.

## 2. Ports and hosts
- Proxy listens on `127.0.0.1:<port>`; default port `8899`, setting `flutterIntercept.port`.
  If busy, take the next free port (8899–8999) and generate the entry with it.
- `PROXY_HOST` (passed to Flutter sessions as `--dart-define=FLUTTER_INTERCEPT_PROXY=<host>:<port>`, never
  baked into the entry; plain-Dart sessions use the entry's `localhost:<port>` default):
  - Android **emulator** (serial `emulator-*`): `10.0.2.2`, **no** `adb reverse`.
  - Android **physical**: `localhost` + `adb -s <id> reverse tcp:<port> tcp:<port>`; run
    `adb -s <id> reverse --remove tcp:<port>` when the proxy stops or the last session ends
    (a stale reverse with no proxy breaks plain-http requests; HTTPS still falls back).
  - iOS simulator, macOS, desktop: `localhost`.
  - iOS physical device: the Mac's LAN IPv4 and the proxy must then listen on `0.0.0.0`.
- Tests in parallel agents: pick random free ports, never 8899 (reserved for Agent A's device runs).

```ts
// `headers`, when present, REPLACES the whole header set. `body` is the decoded text;

export interface RequestEdit  { method?: string; url?: string; headers?: Record<string, string | string[]>; body?: string }

export interface InterceptProxyOptions {
  port: number;
  host?: string;                // default 127.0.0.1
  maxExchanges?: number;        // ring buffer, default 1000
  breakpointTimeoutMs?: number; // auto-resume unedited after this, default 5 min
  ca?: { key: string; cert: string }; // PEM; generated in memory if absent (clients accept any cert)
  ignoreUpstreamCertErrors?: boolean | string[]; // default strict: the proxy still verifies the REAL server
  maxStoredBodyBytes?: number;  // byte budget across stored bodies, default 256 MB
}

Semantics: `clear()` keeps in-flight exchanges (host sends a fresh `snapshot` after `cleared`);
`resume`/`abort` on a non-paused id are no-ops; `resume` throws on an invalid edit and the exchange
stays paused; a client that gives up while paused → state `error` with a message, late resume ignored;
upstream failure → app gets 502, state `error`. The UI must omit `body` from an edit unless edited.
Dependency-free helpers for the webview: `import { matches, ruleFromExchange } from '@flutter-intercept/proxy/rules'`.
mockttp is pinned `~4.6.3` (two patches rely on its internals — docs/spikes/proxy.md).

export class InterceptProxy /* extends EventEmitter */ {
  constructor(opts: InterceptProxyOptions);
  start(): Promise<void>;
  stop(): Promise<void>;
  readonly port: number;        // actual port after start
  setRules(rules: Rule[]): void; // first enabled match wins
  getExchanges(): Exchange[];
  clear(): void;
  resume(id: string, edit?: RequestEdit | ResponseEdit): void; // for paused-request / paused-response
  abort(id: string): void;      // paused → connection reset, state 'aborted'
  on(event: 'exchange', listener: (e: Exchange) => void): this; // full snapshot on every change
  on(event: 'removed', listener: (ids: string[]) => void): this; // ring-buffer evictions
}

// Pure helpers, exported so the webview preview and the host never disagree with the proxy:
export function matches(m: Matcher, method: string, url: string): boolean;
export function ruleFromExchange(e: Exchange, kind: RuleAction['kind'], id: string): Rule;
//   match = { method: e.method, url: <origin+path>* } ; mock = e's response (or 200 "{}"),
//   block = { mode: 'status', status: 403 }, breakpoint = { phase: 'response' }. Host inserts it FIRST.
```

Behaviour: no matching rule → pass through and record. Mock/block never contact the server.
Breakpoint `request` pauses before forwarding; `response` pauses after the real response
arrives and before the app receives it.

## 7. LAN mode — physical iOS devices (added 2026-10-08)

A physical iPhone cannot reach the Mac's loopback, so while (and only while) a physical-iOS session runs,
the proxy also listens on the Mac's Wi-Fi/LAN address. Everything else stays loopback-only.

Proxy API additions (`InterceptProxy`):
```ts
openLan(opts: { host: string; token: string; port?: number }): Promise<{ host: string; port: number }>;
closeLan(): Promise<void>;
readonly lan?: { host: string; port: number };
```
Requirements:
- Bind exactly `host` (a concrete IPv4 of a LAN interface); never `0.0.0.0`/`::`; verify the bound address and
  fail closed, like the loopback bind.
- Every proxy request and CONNECT arriving on the LAN listener must carry
  `Proxy-Authorization: Basic base64("flutter-intercept:" + token)` — compare in constant time; otherwise
  `407` with no details and the connection is closed. Loopback clients are unaffected.
  (Measured: Dart's HttpClient sends these credentials pre-emptively on plain requests AND on CONNECT when
  `findProxy` returns `PROXY flutter-intercept:<token>@host:port`.)
- For LAN clients, refuse upstream targets that are loopback, link-local, unspecified, or any address of the
  Mac's own interfaces (no pivoting into the developer's localhost services); `403`, exchange state `error`.
- `token`: 32 random bytes, base64url, new per proxy LAN opening. Never logged, never shown in the UI.

Extension:
- Physical iOS device ⇒ host = IPv4 of the default-route interface; session define
  `FLUTTER_INTERCEPT_PROXY=flutter-intercept:<token>@<lanIp>:<port>`; the entry passes it into
  `findProxy` unchanged (template must accept the `user:pass@` form).
- `openLan` on the first physical-iOS session, `closeLan` when the last one ends and on deactivate.
- Tell the user once: macOS may ask to allow incoming connections for VS Code; iOS asks for Local Network
  permission on first run — both must be allowed.

### 9.1 Template v4 — request → source (amends §1)
Everything in §1 stays; v4 adds a source trace per request. Still dart:io/async/convert only (no
`dart:developer`, no new imports beyond what §1 lists unless the spike proves one is needed; `dart:math` allowed).
- Every request-opening member of `_InterceptedHttpClient` (`open`, `openUrl`, `get`…`headUrl`) captures
  `StackTrace.current` **synchronously at call time**, picks an opaque id (`/^[A-Za-z0-9_-]{8,64}$/`, unique per
  process incl. hot restarts; no device/user data), and on the returned `HttpClientRequest` sets header
  `x-fi-id: <id>` before handing it to the app.
- Traces go out of band: `POST https://trace.flutter-intercept.invalid/v1/traces`, JSON
  `{"traces":[{"id":"<id>","stack":"<StackTrace.toString(), ≤ 16 KB>"}]}`, batched (≤ 50 per POST, flushed
  within ~100 ms), fire-and-forget, errors swallowed (at most one `_note`). Sent with a **dedicated client that
  is never traced** (no recursion) whose `findProxy` is `PROXY <_proxyAddress>` **without `; DIRECT`**. HTTPS on
  purpose: Android's cleartext policy can block `http://` in dart:io; the host is answered by the proxy with a
  leaf from the trusted install CA. `.invalid` never resolves, so on DIRECT nothing but the opaque `x-fi-id`
  header leaves the device.
- `--dart-define=FLUTTER_INTERCEPT_TRACE=0` (setting `flutterIntercept.captureSource` = false) turns tracing
  off: no header, no side channel. Default on. Flutter sessions only — plain Dart sessions take no dart-define
  (the VM rejects it) and always trace (REVIEW-3 #6, accepted).
- `stack` is the **lean VM format**: frames of `dart:` libraries and of the generated entry are dropped (original
  `#n` numbering kept), `<asynchronous suspension>` kept between kept frames. In debug/JIT sessions earlier
  registration stacks follow, separated by `===== asynchronous gap ===========================` (whole segments,
  at most 10, total ≤ 16 000 chars). In profile, only the synchronous stack. `parseDartStack` (9.2) accepts both
  this and the stack_trace Chain/terse formats.
- **Zone chain (debug/JIT only**, `dart.vm.profile` / `dart.vm.product` false; off with `TRACE=0`): Dio builds its
  pipeline from `Future.then` + `Completer`s, so the synchronous stack ends inside Dio. The app's `main` runs in a
  `runZoned` with `registerCallback` / `registerUnaryCallback` / `registerBinaryCallback` hooks inside the overrides
  zone; a stack is captured only when a `then`/`await` callback is registered (≈1.5–2 µs per await, measured).
- Failure note, printed once per isolate run:
  `[flutter_intercept] request sources are unavailable (could not reach the intercept proxy: <error>)`.
- Spike first (docs/spikes/template-v4.md): does `StackTrace.current` in `openUrl` reach the app's call site
  for Dio (interceptors, `QueuedInterceptor`, transformers) and `package:http` on Dart 3.0–3.13 + current SDK?
  Measure overhead per request. Keep the entry's language-version rules (§1).

### 9.2 Proxy additions (amends §3)
```ts
export interface StackFrame { fn: string; uri: string; line?: number; column?: number; afterAsyncGap?: boolean }
export interface SourceInfo { frames: StackFrame[]; appFrame?: number }   // ≤ 30 frames; appFrame = index
Exchange.source?: SourceInfo;              // set (and 'exchange' emitted) once the trace and the request meet
Exchange.initiator?: 'editor' | 'agent';   // absent = the app
Exchange.resentFrom?: string;              // id of the exchange this one was resent from
Exchange.simulated?: string;               // human label when a throttle/fault/profile affected it
Exchange.viaLan?: true;                    // came through the LAN listener (§7)
Rule.times?: number;                       // rule applies to the first N matching requests, then is spent
Rule.expiresAt?: number;                   // epoch ms; spent after this
Rule.used?: number;                        // host-set hit count for rules with `times` (display only, not persisted)
RuleAction +=
  | { kind: 'throttle'; latencyMs?: number; kbps?: number; dropRate?: number }   // to the real server, slowed
  | { kind: 'fault'; fault: 'reset' | 'timeout' | 'truncate' | 'dns' };
InterceptProxyOptions.rewriteLocalhost?: boolean;  // default true
// network.ts (dependency-free, `@flutter-intercept/proxy/network`): NetworkProfile, NETWORK_PRESETS
// source.ts  (dependency-free, `@flutter-intercept/proxy/source`): parseDartStack, pickAppFrame, FRAMEWORK_PACKAGES

class InterceptProxy {
  send(req: SendRequest): Promise<{ id: string }>;  // resolves once recorded, before completion
  setNetworkProfile(p: NetworkProfile): void; readonly networkProfile: NetworkProfile;
  setAppPackages(names: string[]): void;            // app package names → preferred appFrame
  on(event: 'rule-spent', l: (ruleId: string, reason: 'times' | 'expired') => void): this;
}
```
- **Trace sink**: host `trace.flutter-intercept.invalid` (any scheme/port) is answered locally — 204, never
  forwarded, never recorded, body ≤ 1 MB, bad JSON ignored. Traces wait (≤ 2000, 60 s) for their exchange and
  vice versa; both arrival orders work. Authorised LAN clients may use it (no SSRF check needed: nothing is
  contacted); unauthorised ones still get 407.
- **`x-fi-id`** is removed before anything goes upstream (every route, incl. edits and `send`) and is never in
  `Exchange.requestHeaders`. `appFrame` = first frame whose package is in `setAppPackages` if any, else the first
  frame that is not `dart:`, not the generated entry, not a `FRAMEWORK_PACKAGES` package.
- **`send`**: the request goes through the proxy's own loopback listener like app traffic (rules and the network
  profile apply; recorded with `initiator`/`resentFrom`); upstream TLS stays strict. Invalid method/URL rejects.
  Recorded `content-length` / `transfer-encoding` / connection headers are ignored (framing recomputed) and
  `Host` always comes from the URL. Hosts strip `proxy-authorization` (may carry the LAN token) and `x-fi-id`.
- **throttle**: `latencyMs` before forwarding, `kbps` caps the response body speed to the app (streaming
  Transform in taps/flow, no full buffering), `dropRate` (0–1) = probability the exchange is reset instead.
  **fault**: `reset` after the tunnel is up; `timeout` holds it unanswered until the client gives up (≤
  `breakpointTimeoutMs`, then reset); `truncate` forwards, then cuts the response body mid-way; `dns` = the
  closest the app can see to a failed lookup. Measured with the real Dart client and written down in
  docs/spikes/faults.md — **a fault must never make Dart fall back to DIRECT** (i.e. never fail the connection
  to the proxy itself). Faulted exchanges end `blocked`; throttled ones end normally; both set `simulated`.
- Measured app view (docs/spikes/faults.md): reset/drop → `Connection reset by peer`; `dns`/offline → closed
  without a response (`Connection closed before full header was received`) — a real connect-time
  `SocketException` is impossible through a proxy without DIRECT fallback; timeout → the app's own timeout, else a
  reset at `breakpointTimeoutMs`; truncate → status then `Connection closed while receiving data`. Not throttled:
  uploads (kbps), websockets.
- A throttle rule **replaces** the profile for the requests it matches. Under `offline` a request breakpoint fails
  instead of pausing. `setNetworkProfile` throws on invalid input (host → `error`).
- **Network profile** (global, this proxy = this app only): applies to everything that would reach the network
  (pass-through, breakpoints, throttle rules, `send`); mock/block/fault rules still answer as configured; the
  trace sink is never affected. `offline` = the `dns`-style fault for every request.
- **Rule spending**: hit counts are keyed by rule id and survive `setRules` (dropped when the id disappears); a
  rule whose `times` is used up or whose `expiresAt` passed no longer matches and `rule-spent` fires once (an
  expiry timer fires it even without traffic). The host removes spent rules (9.4). For rules with `times`,
  `on('rule-hit', (ruleId, used) => …)` fires on every hit; the host sets `Rule.used` and re-broadcasts `rules`.
- **rewriteLocalhost** (loopback-listener clients only; LAN clients keep the §7 SSRF guard, unchanged):
  targets `10.0.2.2` / `10.0.3.2` (emulator aliases for the host) are connected to `127.0.0.1` on the same port;
  `localhost` / `127.0.0.1` already reach the host machine because the proxy runs there — verify, including
  mockttp's own loop protection. `Exchange.url` stays what the app sent.

### 10.1 Principles
- The **wire contract is `_$XFromJson` in `*.g.dart`** (json_serializable; freezed delegates to it), not the

- Everything agents read stays redacted (§8); codegen and fixtures use the redacted view.

### 10.2 Proxy: `mutate` rule action
`{ kind: 'mutate'; ops: MutateOp[] }` — forwards to the real server, then changes the JSON response before the
app gets it (`null` / `delete` / `set` at a `jsonpath.ts` path; `[*]` expands). Buffered like a response
breakpoint (h2 route, ≤ 32 MB), re-framed (content-length / encoding) like edits. Non-JSON or unparsable body →
forwarded unchanged with a note in `Exchange.error` (state stays `completed`). Sets `Exchange.simulated` to e.g.
`Mutated: $.avatar_url → null`; `matchedRuleId` as usual. Counts toward `times`. Under the network profile it
behaves like any pass-through. `jsonpath.ts` is dependency-free and shared with the webview and the agent API.
Measured semantics (docs/spikes/proxy.md v0.4.0): `set` may create a missing last object key, `null` / `delete`
never create; ops that match nothing are reported in `error` on a `completed` exchange; applies to any status
(error bodies too); output is compact JSON with **number literals kept byte-exact** (`1.0` stays a double for
Dart; ints past 2^53 stay exact); body > 32 MB decoded → forwarded unchanged with a note, but > 32 MB **on the
wire** still fails with the response-breakpoint 502 (mockttp buffers before `beforeResponse`). Chunked or > 5 MB
request bodies skip the rule with a note, like breakpoints. `ruleFromExchange(e, 'mutate', id)` returns
`{kind:'mutate', ops: []}` for the host to fill.
`MutateOp.valueJson?: string` (and `mutateField.valueJson`): the `set` value as JSON text, written byte-exact; wins
over `value`; must parse. UIs and agents send it whenever the literal matters (`1.0`, big ints).

`mock.bodyFile` = workspace-relative path (inside the workspace, realpath-checked, regular file ≤ 5 MB). The host
reads it into `body` before handing rules to the proxy and re-applies on change; a missing file → the rule is
skipped with a problem shown. The editor offers "Edit body in a file" (creates `.vscode/flutter-intercept/mocks/<name>.json`).

### 12.3 Scenarios and auth flows
- `sequence` (proxy): steps answer successive matching requests (`count` each, default 1); afterwards `then`:
  `last` (keep the last step, default), `passthrough`, or `loop`. Counters per rule id, reset when the rule changes
  or on `resetSequences()`; `rule-hit` reports the step. Steps can't be `breakpoint`/`sequence`.
- **Expire token** preset (`expireToken {url, count}`): sequence `[mock 401 {"error":"token_expired"} × count,
  passthrough]`, named "Expire token: …".
- **Auth analysis** (`src/analysis/**`, pure): from exchanges, find 401/403 → refresh call(s) (POST/GET to a URL
  matching /(refresh|token|oauth|auth)/i or the same origin's auth endpoints) → retried request(s); `stampede` when
  ≥ 2 refresh calls follow one expiry within 2 s; `problem` when the retry is missing or gets 401 again. The host
  pushes `authFlows` to the panel (debounced) and agents can read them.

### 12.4 Record → replay
- `RecordingService` (`src/recordings/**`): save finished HTTP exchanges (not WebSocket/SSE/vm-profile) to
  `.dart_tool/flutter_intercept/recordings/<id>.json` (gitignored location; unredacted by default because replay
  needs real bodies; `redact: true` option), list / load / delete / export.
- Proxy `setReplay(entries: ReplayEntry[] | undefined, opts: ReplayOptions)`: while set, a request is answered from
  the recording — exact method + URL (+ request body hash for bodies), then (with `matchTemplates`) method + path
  template; several recorded responses for one key are served in order and the last repeats.
  `ReplayEntry.requestBodyHash` = lowercase hex sha256 of the **decoded** request body bytes (utf8 text as UTF-8,
  base64 decoded), omitted for empty/truncated bodies; `toReplay` strips framing headers, the proxy re-frames. Rules still win
  (they are checked first). Unmatched: `passthrough` or `fail` (like offline). Exchanges answered by replay end
  `mocked` with `simulated: "Replayed from <name>"`.

### 12.5 Diff two recordings
`RecordingService.diff(a, b)` by route (method + path template): added / removed routes, status changes, JSON
shape changes (keys added/removed, type changes), body value changes (count only), call-count changes, timing
(> 2× slower). `diffText` gives a normalised text for `vscode.diff` (bodies pretty-printed, volatile headers such
as date / set-cookie values / request ids dropped).

### 12.6 Map Remote, rewrite, upstream proxy (proxy)
- `mapRemote {to}`: `to` is an origin (`https://staging.example.com`) or URL prefix; the request is forwarded there
  (path/query kept after the matched prefix), `Host` from `to` unless `preserveHost`; upstream TLS verified as
  usual; the app sees the original URL; `simulated: "Mapped to <origin>"`. LAN clients keep the §7 SSRF guard on
  the **mapped** target.
- `rewrite`: request headers set/removed before forwarding; response status/headers set/removed; literal body
  find/replace (decoded text, ≤ 20 replacements, re-framed like edits; non-text bodies untouched with a note).
- `upstreamProxy` option (setting `flutterIntercept.upstreamProxy`): all pass-through traffic goes via that HTTP
  proxy (CONNECT for HTTPS); `ignoreCertErrors` only when the user sets it (needed for MITM proxies like Charles).

### 12.7 UI and agents
- Webview: rule editor for `sequence` (step list), `mapRemote`, `rewrite`, `bodyFile`; a "Shared" badge and
  Share toggle; a banner when shared rules await approval (button → `approveSharedRules`); Recordings view (save
  current traffic, replay with fallback choice, diff two, delete), a clear "Replaying <name>" status indicator;
  "Auth flows" view (timeline of 401 → refresh → retry, stampede warning); "Expire token" action on a request.
- Agent tools: `save_recording {name, url?, sinceMs?, redact?}` (W), `list_recordings` (R),
  `replay_recording {id?, fallback?}` (W; omit id = stop), `diff_recordings {a, b}` (R; entries, redacted details),
  `add_sequence {url, method?, steps, then?, name?}` (W), `expire_token {url, count?}` (W),
  `add_map_remote {url, to, method?}` (W; **agents may only map to loopback targets** — local backends),
  `add_rewrite {...}` (W; agents can't set request headers whose names match the redaction rules),
  `get_auth_flows {sinceMs?}` (R). Globs only, redacted views, confirmations name targets.
- Added while building: view → host `openSharedRules` (opens the shared file) and `openBodyFile {path, create?}`
  (opens a mock body file inside the workspace, creating it only if missing); `Status.sharedRules.pending`
  lists each held rule's name and reason (the approval modal shows the same text).

### 12.8 As built (proxy, v0.6.0)

### 13.4 JavaScript scripting hooks (proxy + rules + webview)
- Rule action `{kind:'script', code, file?}`. The script defines either or both:
  `function onRequest(request, context)` → return an edited `ScriptRequest` (forwarded), `{ response:
  ScriptResponse }` (answered locally, like a mock; state `mocked`), or `undefined` (unchanged);
  `function onResponse(response, request, context)` → an edited `ScriptResponse` or `undefined`.
  `context = { ruleId, exchangeId, log(...args) }`; log lines go to `Exchange.scriptLog` (≤ 20 × 500 chars).
- Execution (proxy, `src/script.ts`): one `worker_threads` Worker per InterceptProxy, started lazily while any
  script rule is set, created from source (`eval: true`, no extra bundle file), `resourceLimits` (64 MB old space);
  each script compiled once in its own `vm` context (`codeGeneration: {strings: false, wasm: false}`, no `require`,
  `process`, timers, `fetch`, `import()` — only plain JS builtins); synchronous hooks only; 200 ms per call (vm
  `timeout`), a 1 s watchdog terminates and restarts the worker. Inputs and results cross as JSON (structured clone),
  are validated like edits (`validateEdit` rules: status 100–599, header names/values, body ≤ 5 MB) and re-framed
  like edits. Bodies over 1 MB or binary → `body` absent, `bodyOmitted: true` (a returned body then replaces it).
- A hook that throws, times out or returns something invalid → the app gets `502`, state `error`, `error` =
  "Script <rule name>: <message>", the message also in `scriptLog`. Not applied to WebSocket upgrades (refused at
  validation) or vm-profile captures. Not a security sandbox: scripts are trusted code.
- Trust (rules + host): personal script rules are the user's own. **Every shared script rule needs approval**
  (§12.1 gate; the approved hash covers the script file contents). `script.file`: workspace-relative `.js`, inside
  the workspace (realpath-checked), regular file ≤ 256 KB; changes re-resolve (and re-hold a shared rule). Editor
  "Edit script in a file" creates `.vscode/flutter-intercept/scripts/<name>.js` from a template.
- **Agents can't create, edit or read scripts**: no agent tool adds them; agent views of a script rule show
  `{kind:'script', file?}` without `code`; `scriptLog` is redacted like bodies.

### 14.2 TLS passthrough hosts (proxy + host + webview)

'tunnel'`, `method: 'CONNECT'`, `url: https://host:port/`, `tunnelBytes`, timings up to the tunnel opening, state
`completed` / `error`. Rules never apply (only `block` and faults on the CONNECT, like WebSockets). LAN clients keep the

### 14.5 WebSocket / SSE recordings (recordings + proxy replay)

`redact`); `toReplay` emits `ReplayEntry {kind, frames}`. Proxy replay: **SSE** → answer with the recorded head and the
events at their recorded relative times (capped at 5 s gaps); **WebSocket** → accept the upgrade locally and act as a
scripted server: send the recorded server frames that preceded the first client frame, then after each client frame
the server frames that followed it in the recording (timing kept, gaps ≤ 5 s); close like the recording. Diff: frame
counts per route and message-type changes. Agents: `save_recording` includes them.

### 15.1 Architecture
```
Android Studio ── plugin (Kotlin) ──stdio JSON──▶ node sidecar.js ──▶ InterceptProxy (mockttp), controller, agent API (MCP)
      │ JCEF tool window ◀── http://127.0.0.1:<ui>/?t=<token>  (webview bundle + WebSocket for HostMsg/ViewMsg)
      └ Flutter run configs ── prepareLaunch → generated entry (-t) + --dart-define (FLUTTER_INTERCEPT_PROXY, …)
```
- **Sidecar** (`packages/sidecar`, TypeScript, one esbuild bundle `dist/sidecar.js`): composes the vscode-free extension
  modules (proxyHost, ui/controller, agent api + mcp server, rules core, recordings, contract, codegen, export, notify

- **UI server** (sidecar): binds 127.0.0.1 on a random port; one random token per sidecar run (32 bytes, base64url);
  `GET /?t=<token>` returns the webview HTML (same CSP as §4 with `connect-src ws://127.0.0.1:<port>`), the bundle
  and an IDE theme stylesheet (`--vscode-*` variables for light / dark / high contrast); `GET /ws?t=` upgrades to a
  WebSocket carrying `HostMsg` / `ViewMsg` JSON. Requests without the token, with a foreign `Host`, or with an `Origin`
  other than the UI origin are refused (403). Several JCEF clients may attach (one per project window).
- **Webview standalone mode** (`packages/webview`): when `acquireVsCodeApi` is absent, `host.ts` talks over that
  WebSocket (URL + token from the page), reconnects with backoff, and state persistence uses `sessionStorage`; the
  UI is otherwise identical. `body.fi-ide` selects IDE layout tweaks; theme variables come from the stylesheet.
- **Plugin** (`packages/intellij`, Kotlin, Gradle with the IntelliJ Platform Gradle Plugin 2.x): starts the sidecar
  lazily with the user's Node (setting `nodePath`, default `node` on PATH; Node ≥ 18 checked, clear notification
  otherwise), one sidecar per IDE process (application service) shared by project windows; restarts it on crash
  (backoff, ≤ 3 times / 5 min); kills it on exit. Tool window "Flutter Intercept" (bottom) with a JCEF browser on
  `uiUrl` (fallback message when JCEF is unavailable). Status bar widget (on/off, paused count). Settings page
  (Tools → Flutter Intercept) storing `SidecarSettings` application-level; passphrases in `PasswordSafe`. Actions:
  Toggle Interception, Open Traffic, Clear, Connect AI Agent (copies `connectAgent` text), Export OpenAPI / Postman,

  FileChooser/FileSaverDialog, Messages, notifications, DiffManager, LightVirtualFile).
- **Run integration** (plugin `run/**`): before a Flutter run configuration (`io.flutter.run.SdkRunConfig` and
  related) launches in debug or profile mode, call `prepareLaunch`; on `Rewrite`, launch with the generated entry and
  the extra args **without permanently changing the user's run configuration** (a copy or a transient patch that is
  always restored); `Skip` → unchanged + the reason logged once. Device id/kind from the Flutter plugin's device

### 15.4 Android Studio has no JCEF (as built)

### 16.1 Entry template v6 (amends §1, §13.3)
v5 plus a `Socket.connect` hook, dart:io / dart:async / dart:convert only:
- Installed from `_install()` (main isolate and `flutterInterceptInstall()` for background isolates), as
  **`IOOverrides.global` only — never in the zone** (a zone install shadows the app's own later `IOOverrides.global`).
  Not a subclass (`IOOverrides` is `abstract base`): the instance is `IOOverrides.runZoned(() => IOOverrides.current!,
  socketConnect: …)`. The previous global (if any) is kept for direct connects.
- Redirects **only** connects whose `StackTrace.current` contains `package:grpc/src/client/http2_connection.dart` or
  `package:connectrpc/src/http2/connection.dart`; Unix-domain addresses and everything else go direct through the
  previous / plain overrides. `--obfuscate` / `--split-debug-info` builds lose the frame → direct (documented).
- Off when `--dart-define=FLUTTER_INTERCEPT_GRPC=0` (setting `flutterIntercept.grpc.enabled: false`) and when no
  proxy define is present (plain Dart sessions keep the `localhost:<port>` default like v5).
- **Silent CONNECT**: connect to the proxy address from `FLUTTER_INTERCEPT_PROXY` (`[user:token@]host:port`; hop
  timeout 2 s or the app's `connectTimeout` if shorter), write exactly
  `CONNECT <authority> HTTP/1.1\r\nHost: <authority>\r\nFlutter-Intercept-Tunnel: silent\r\n`
  `[Flutter-Intercept-Connect-Timeout: <ms>\r\n][Proxy-Authorization: Basic <b64(user:token)>\r\n]\r\n` and return the
  socket at once (no reply is ever read). `<authority>` = `host:port`, IPv6 in brackets, `InternetAddress` → its
  `address`. Proxy unreachable → direct connect with the remaining timeout.
- **Circuit breaker** (spike: reconnect storms): ≥ 3 tunnels to one authority within 2 s → that authority goes direct
  for 30 s, per isolate.
- `docs/spikes/template-v6.md` records device results (Android emulator, iOS simulator, macOS, plain Dart) and Dart
  SDK range; the generator's golden tests cover v6.

### 16.2 Proxy (amends §3, §14.2)
- mockttp runs with `http2: 'fallback'` (HTTP/1.1 clients and Chrome unchanged; `[grpc-exp, h2]` gets `h2`).
- **Silent tunnels** (`onConnect`): a CONNECT carrying `Flutter-Intercept-Tunnel: silent` (case-insensitive) gets **no
  reply**. Same checks as any CONNECT (LAN gate token / pinned peer, passthrough hosts, block / fault rules on the
  CONNECT); the marker and connect-timeout headers never go upstream. The head and the first payload may share a chunk
  (split at `\r\n\r\n`). Then by the first payload byte:
  - `PRI * HTTP/2.0` preface (h2c) → injected into mockttp like its own CONNECT minus the 200 (`LastTunnelAddress`,
    `LastHopEncrypted = false`, timing symbol, `unshift`, `emit('connection')`).
  - `0x16` (TLS) and the host matches `grpcDecryptHosts` (and not `tlsPassthrough`) → injected the same way (MITM).
  - `0x16` otherwise → the §14.2 passthrough tunnel (no reply written): `Exchange {kind: 'tunnel', grpcTunnel: true}`.
  - anything else → closed, recorded as an `error` tunnel.
  - Refusals (bad token, SSRF guard) can't be answered on a silent tunnel: close, record, and rely on the entry's
    breaker. Caps: silent tunnels count toward the LAN gate's connection caps.
- **gRPC calls**: an HTTP/2 request with `content-type` `application/grpc`, `application/grpc+…` or
  `application/grpc;…` (not `grpc-web`) is handled by our own `node:http2` relay inside a mockttp step (spike
  `grpc-relay.js`), never mockttp's passthrough. Exchange: `kind: 'grpc'`, `method: 'POST'`,
  `url: http(s)://<authority>/<pkg.Service>/<Method>`, request/response headers, `responseTrailers`, `status` = the HTTP
  status, `grpc: GrpcInfo`, `frames` = one `{kind: 'message'}` frame per length-prefixed message each way (decompressed
  for `grpc-encoding: gzip` with `compressed: true`; `base64` ≤ 64 KB, `size` = full decompressed size; counting goes on
  past the frame cap). `state`: `pending` while open, `completed` when trailers arrive (any grpc-status), `aborted` on a
  client cancel, `error` on a reset without status. Timings as §13.2 (`waitMs` = request headers sent → response
  headers).
- **Upstream**: `http2.connect(origin, {createConnection})` over a socket from the existing tunnel upstream path (LAN
  SSRF guard, upstream proxy, emulator aliases, `rewriteLocalhost`); `https` → TLS with ALPN `h2`, honouring
  `ignoreUpstreamCertErrors` and client certificates (§14.3); `http` → h2c prior knowledge. Sessions pooled per origin
  and per LAN gate; GOAWAY / max-concurrent-streams / idle 30 s handled. `Flutter-Intercept-Connect-Timeout` honoured
  (default 30 s, max 60 s). Upstream failure → trailers-only `grpc-status: 14` with
  `grpc-message: Flutter Intercept: <reason>` (never a bare close). Client cancel → `RST_STREAM CANCEL` upstream;
  `grpc-timeout` forwarded unchanged.
- **Rules on gRPC calls** match `method` `POST` and the URL above. Applicable actions: `grpcMock`; `block`
  (`status` → trailers-only `grpc-status 14`, `grpc-message: Blocked by Flutter Intercept`; `reset` → RST_STREAM);
  `fault` (`reset` → RST_STREAM INTERNAL_ERROR, `timeout` → no answer until the client gives up, `truncate` → headers +
  first response message then RST_STREAM, `dns` → trailers-only `14` "DNS lookup failed"); `throttle` and the network
  profile (latency before the first response bytes, `kbps` / `uploadKbps` pacing each direction, `dropRate` → `14`);
  `sequence` whose steps use those actions. **Rules with any other action never match a gRPC call** (the next rule is
  tried). Breakpoints, mutate, rewrite, script, cors, mapRemote and replay don't apply to gRPC in 0.10.
- `grpcMock` answers locally: `delayMs`, then response headers (`content-type: application/grpc`, plus `headers`), then
  each of `messages` (base64 protobuf payloads, framed uncompressed) `gapMs` apart, then trailers `grpc-status: code`
  (default 0), `grpc-message` (percent-encoded), plus `trailers`. `code ≠ 0` with no messages → trailers-only. Pseudo
  headers, `content-type`, `grpc-status`, `grpc-message` in `headers` / `trailers` are refused by `setRules`. A mock
  doesn't wait for the client to half-close (bidi). `messagesJson` is resolved by the host before `setRules` (like
  `bodyFile`); the proxy ignores it.
- `setGrpcDecryptHosts(hosts) → {hosts, problems}` (same host-pattern rules as `setTlsPassthrough`);
  `grpcSupport() → {ok: boolean; problem?: string}` from a startup self-check of the mockttp internals used (else
  silent tunnels with h2c / decrypt fall back to passthrough tunnels and the problem is reported).
- HTTP/2 traffic that isn't gRPC keeps mockttp's passthrough (known: h2c upstream 502, trailers-only lost) — documented.

### 16.3 Extension: protobuf schema from the app's generated code (`src/grpc/**`, pure, no vscode)
Like §10.3 (`*.g.dart` is the wire contract), the app's **protoc-generated Dart** is the gRPC contract:
- `*.pbgrpc.dart`: `ClientMethod<Req, Res>('/pkg.Service/Method', …)` → method path → request / response message
  types; streaming from the `$createUnaryCall` / `$createStreamingCall` call and `$async.Stream<…>` parameters.
- `*.pb.dart`: each `$pb.BuilderInfo(... 'Name', package: ... 'pkg', ...)` chain (`a`, `aOS`, `aOB`, `aI`, `aInt64`,
  `aOM`, `aQM`, `p`, `pc`, `pPS`, `e`, `pc<Enum>`, `m`, `oo`, `hasRequiredFields`, `$pb.PbFieldType.*`) → message
  fields (number, json name, type, repeated / map / oneof, message or enum type); `*.pbenum.dart` → enum values. The
  name passed in the builder chain (`_omitFieldNames ? '' : 'x'`) is the JSON name. Nested messages (`Outer_Inner`
  ↔ `Outer.Inner`).
- Sources: every workspace folder and the path / hosted packages in `.dart_tool/package_config.json` that contain
  `*.pbgrpc.dart` (caps: 5000 files, 2 MB each, 50 MB total; no symlinks out of roots; regex / tokenizer only, never
  executing anything).
- API (`src/grpc/types.ts`): `loadGrpcSchema(files) → GrpcSchema`; `schema.method(path)`, `schema.message(name)`;
  `decodeMessage(schema, type, bytes) → {json, unknown?}` (proto3 JSON: int64 as strings, bytes base64, enums by name,
  unknown fields under `"#<n>"`), `decodeRaw(bytes)` (`protoc --decode_raw` style, field numbers, nested-message and
  UTF-8 guesses, depth ≤ 32), `encodeMessage(schema, type, json) → bytes` (for mocks; errors name the JSON path),
  `skeleton(schema, type)` (example JSON with every field). All bounded (≤ 4 MB input, ≤ 100k fields).

### 16.8 REVIEW-10 amendments
- **Held, not closed (REVIEW-10 #1).** A silent passthrough tunnel (undecrypted TLS gRPC) that a block rule, the
  offline profile, `replay: fail` or a throttle drop cuts is **held**: no bytes relayed either way, the app's socket
  kept open until the app closes it or `breakpointTimeoutMs` passes (then reset). The exchange shows the reason as
  today. To grpc-dart that is an unreachable network (its deadline fires), not a connected-then-lost connection, so no
  reconnect storm and no breaker trip. Normal (non-silent) tunnels keep the §14.8 behaviour.
- **Breaker report.** When the entry's breaker trips for an authority it opens one more connection to the proxy and
  writes `CONNECT <authority> HTTP/1.1\r\nHost: <authority>\r\nFlutter-Intercept-Tunnel: breaker\r\n`
  `[Proxy-Authorization: …\r\n]\r\n`, then closes it (best effort, never awaited by the app's connect). The proxy runs
  the same LAN checks, records no exchange, and emits `'grpcBreaker' {authority, viaLan}` (once per authority per
  60 s). The host shows `SessionWarning {kind: 'bypass', id: 'grpc-breaker:<authority>'}`: "gRPC connections to
  <authority> kept closing, so the app connected directly for 30 s — rules and network simulation didn't apply to
  them meanwhile." The entry's console note says the same.
- **Decompression (REVIEW-10 #3).** Only kept message bytes are decompressed, streaming, stopping after the frame cap
  (64 KB) + 1 byte of output; messages past the frame cap are counted, never decompressed. When decompression stopped
  early the frame has `sizeUnknown: true` and `size` = the compressed (wire) size; the UI shows "≥ 64 KB".
- **Relay hardening (REVIEW-10 #6).** `decideGrpc` applies the REVIEW-8 client-certificate Origin refusal (trailers-only
  `14`); no doubled "Flutter Intercept:" prefix in `grpc-message`.
- **Status codes**: `grpcMock.code` is an integer 0–16 everywhere (agent schema, host validation, proxy).
- **Schema (REVIEW-10 #2, #4, #6)**: parsing is linear-time with a per-file budget (≈ 2 M tokens or 200 ms → skipped
  with a problem "too complex to read"); problem texts use the display label (`GrpcSourceFile.label`: root-relative or
  `package:<name>/…`), never an absolute path; Node errors as codes (`EACCES`, `ENOENT`); decoded JSON keeps
  `__proto__` as an own property.
- **Agents (REVIEW-10 #4, #5, #6)**: problems scrubbed of absolute paths as a backstop; `list_rules` shows grpcMock
  `messages` as `get_request` would (schema decode → redacted JSON, else raw decode redacted by value, else
  `[binary N bytes]`) and HTTP `mock.body` through `redactBodyText`; confirmations show only validated values; tool
  descriptions say that without the app's generated code redaction is by value only.


## 17. v0.11.0 — gRPC parity (2026-10-11)

Goal: the HTTP tools that 0.10 left out for gRPC — **breakpoints**, **mutate**, **recordings / replay / diff** — plus
**`.proto` files** as a schema source. Owner: "take every decision in the project's interest". Plan and owners:
docs/PLAN.md "v0.11.0". Hook map (as of 0.10): the relay pipes bytes (`grpcRelay`, `Observer` links), so 0.11 replaces
the observer links with a **message-reframing transform** that can hold or rewrite whole messages without breaking
backpressure or HTTP/2 flow control. Types already in code: `packages/proxy/src/types.ts` (`GrpcPause`, `GrpcEdit`,
`GrpcProxyCodec`, `ReplayEntry.kind 'grpc'` + `grpc`, `Exchange.grpcPause`), `packages/webview/src/protocol.ts`
(`GrpcDecoded.paused`, `RecordingSummary.grpc`), `packages/extension/src/grpc/types.ts` (`ProtoMessage.source`,
`GrpcMethod.source`).

### 17.1 Proxy: message transform (replaces the observer links)
- Request and response directions of a relayed call run through a `GrpcMessageTransform` that parses whole messages
  (5-byte header + payload), records them as today (frame cap 64 KB, counts, §16.8 decompression), and for each
  message either forwards it unchanged (default, zero-copy when no hook applies), **holds** it (breakpoint), or
  **replaces** it (mutate / breakpoint edit), re-framed with `frameMessage`. Replaced messages are sent **uncompressed**
  (flag 0 is legal per message whatever `grpc-encoding` says). Holding = not calling the transform callback, so
  HTTP/2 flow control pushes back on the sender.
- Whole-message cap for hooks: 4 MB (decompressed for compressed messages, bounded as §16.8). A larger message is
  forwarded unchanged and the exchange gets a note ("message over 4 MB: not paused / not mutated").
- The fast path (no breakpoint / mutate rule for the call) must stay as cheap as 0.10 (no per-message copies).

### 17.2 Breakpoints on gRPC
- A `breakpoint` rule now applies to gRPC calls (`grpcApplicable` += breakpoint, mutate). Phase `request` holds each
  message the app sends; `response` holds each message the server sends **and** the end of the call (the trailers);
  `both` = both.
- While held: `Exchange.state` `paused-request` / `paused-response`, `pausedAt`, `pauseDeadline`, and
  `grpcPause` = `{kind: 'message', dir, index, base64, size}` (the full held message, ≤ 4 MB) or `{kind: 'status',
  code, message?, trailers}` (the trailers the server sent; a trailers-only response is held as status too).
- `resume(id, edit?: GrpcEdit)`: for a message pause `{message: base64}` replaces it, `{drop: true}` drops it (the
  index of later messages is unchanged in the record; dropped messages are recorded with `dropped: true`); for a status
  pause `{status: {code 0–16, message?}, trailers?}` replaces the final status / custom trailers (pseudo,
  `content-type`, `grpc-status`, `grpc-message` refused inside `trailers`). `messageJson` is host-only (encoded with the
  schema before `resume` reaches the proxy, like `grpcMock.messagesJson`). `abort(id)` → `RST_STREAM CANCEL` both ways.
  Auto-resume unedited after `breakpointTimeoutMs`. Messages behind a held one wait (order is kept); the other
  direction keeps flowing.
- Pausing never holds a whole streaming call open forever: each pause has its own deadline.

### 17.3 Mutate on gRPC
- `mutate` rules apply to **response messages** of matching gRPC calls: decode with the codec the host injects
  (`setGrpcCodec`), `applyOps` (same JSON path subset), encode, forward. No codec / unknown method / decode failure →
  the message is forwarded unchanged and the exchange gets a note ("mutate: no schema for /pkg.Svc/Method"). Proto3 JSON
  rules apply (`valueJson` "42" for int64 strings etc.); an encode error (e.g. a string into an int32) forwards the
  original and notes the JSON path.
- `InterceptProxy.setGrpcCodec(codec?: GrpcProxyCodec)`: `decode(path, dir, bytes) → json | undefined` and
  `encode(path, dir, json) → Uint8Array` (throws with a JSON-path message), synchronous, called only for messages a
  hook needs. The host passes one backed by its schema service (VS Code and the sidecar; the CLI passes none).

### 17.4 Recordings, replay and diff with gRPC
- Recording format **version 3** when a recording contains gRPC calls (2 with WS/SSE only, 1 otherwise). A gRPC entry:
  `kind: 'grpc'`, method POST, URL, request / response headers, `frames` (message frames both ways, as recorded:
  ≤ 64 KB each), `grpc: {code, message?, trailers?, requestHash?}` (`requestHash` = sha256 of the first request
  message, to tell unary calls apart). Calls with a truncated or `sizeUnknown` response message are saved with
  `incomplete: true` and are not replayed (fallback applies). Redacted recordings: with a schema, messages are decoded,
  redacted like agents see them, re-encoded; without one, binary messages become zero bytes of the recorded size.
- Replay: a gRPC entry answers like a `grpcMock` (recorded response headers minus pseudo / content-type, the recorded
  response messages with their recorded gaps capped at 5 s, then the recorded status and trailers). Matching: path,
  then `requestHash` when several entries share a path, else the next unused entry for that path in order, then the
  last one. Unmatched gRPC calls follow `fallback` (passthrough / `14 Not in the recording`, as 0.10).
- Diff: route key `gRPC /pkg.Service/Method`; status code changes, message count changes per direction, and, when the
  schema decodes both sides, JSON shape changes of the first response message (same shape diff as HTTP bodies).
- Agents: `save_recording` / `replay_recording` / `diff_recordings` include gRPC; `RecordingSummary.grpc` counts them.

### 17.5 `.proto` files as a schema source (`src/grpc/**`, pure)
- `loadGrpcSchema` also accepts `*.proto` files (proto2 / proto3 / editions syntax subset: package, import, message,
  nested message / enum, fields with labels, maps, oneofs, options ignored, services with rpc + `stream`, `json_name`,
  `reserved`, `extensions` skipped with a problem; groups → problem). JSON names follow protoc (lowerCamelCase unless
  `json_name`). Imports resolve by path suffix among the loaded `.proto` files; `google/protobuf/*` uses the built-in
  well-known types.
- When a message or method is defined by both generated Dart and a `.proto`, the generated Dart wins (it is what the
  app runs); `source` tells which one was used. Same budget and caps as §16.8.
- Discovery (host): `**/*.proto` in the workspace folders too (skip `node_modules`, `build`, `.dart_tool`, `Pods`,
  `.git`; caps shared with the Dart files).

### 17.6 Host, agents, webview
- Host: `setGrpcCodec` wired in VS Code and the sidecar; `resume` with `GrpcEdit.messageJson` encoded with the call's
  request / response type (errors back to the caller, the call stays paused); `decodeGrpc` also returns `paused` (the
  held message decoded in full, ≤ 4 MB) for a paused call.
- Agents: `add_breakpoint` / `add_mutation` describe gRPC; `list_paused` / `get_request` show `grpcPause` (decoded,
  redacted); `resume_request` takes `grpc: {messageJson? | message? | drop? | status? + trailers?}`; recordings tools
  per §17.4.
- Webview: a gRPC pause editor (JSON editor of the held message with Resume / Drop / Abort; a status editor for the end
  of the call), breakpoints and mutate offered on gRPC rows and in the rule editor (the 0.10 "doesn't apply to gRPC"
  notes removed for them), recordings show gRPC counts.

### 17.7 Security review items
The transform's caps (4 MB hold, decompression bound), held-message memory per call and in total (≤ 64 MB of held
messages across calls, beyond that new pauses are skipped with a note), codec calls bounded (no recursion bombs:
§16.3 limits), recordings never write unredacted messages when `redact` is set, `.proto` parser bounded and linear,
`resume` edits validated (base64, size, status range, trailer names).

Goal: the last HTTP tools that skip gRPC calls — **rewrite**, **scripts**, **map remote** and **resend / edit &

every decision in the project's interest. Plan and owners: docs/PLAN.md "v0.12.0". Types already in code:

`SendRequest.grpc`). After 0.12 `grpcApplicable` covers every rule action except `cors` (browser-only) — and `mock`
(HTTP bodies; gRPC has `grpcMock`).

### 18.1 Rewrite (metadata)
- `rewrite.request.setHeaders / removeHeaders` change the gRPC request metadata before it goes upstream;
  `rewrite.response.setHeaders / removeHeaders` the response headers; new `rewrite.response.setTrailers /
  removeTrailers` the trailers (custom metadata only). Pseudo headers, `content-type`, `te`, `grpc-encoding`,
  `grpc-accept-encoding`, `grpc-status`, `grpc-message`, `grpc-timeout` are refused in set / remove (status changes use a
  breakpoint, mutate or a `script`); `-bin` values must be valid base64. `replaceBody` and `response.status` don't apply

### 18.2 Scripts
- A `script` rule's code may also define `onGrpcMessage(message, context)` and `onGrpcStatus(status, context)`; HTTP
  hooks (`onRequest` / `onResponse`) are not called for gRPC calls and vice versa.
- `onGrpcMessage` receives `GrpcScriptMessage {path, dir, index, json?, base64, size}` for every message of a matching
  call (both directions), `json` decoded with the host codec (absent with no schema / over 1 MB). Return `undefined`

  `{base64}`, or `{drop: true}`. `onGrpcStatus` receives `GrpcScriptStatus {path, code, message?, trailers}` before

  edit). Same sandbox, time limit per call (the 0.7 script limits), `context.log` → `scriptLog`; a throw → original
  passes, error logged. Hooks run on the 0.11 message transform (hook path only when a script rule matches).

### 18.3 Map remote
- `mapRemote.to` (origin or URL prefix) sends a matching gRPC call to another server: upstream session to the mapped
  origin (same LAN SSRF guard, upstream proxy, client certificates for the new host), `:authority` = the new host unless
  `preserveHost`, `:path` rewritten by prefix like HTTP. `https` targets use TLS + ALPN h2, `http` targets h2c. The
  exchange keeps the app's URL and gets `simulated: "Mapped to <origin>"` like HTTP. Shared-rule approval as today.

### 18.4 Resend / edit & resend
- `InterceptProxy.send` accepts `SendRequest.grpc = {messages: string[] (base64)}` for a gRPC URL
  (`/pkg.Service/Method`, method POST): the proxy opens its own HTTP/2 call (same upstream path as the relay,
  `content-type: application/grpc`, `te: trailers`, the given headers minus pseudo / hop-by-hop / `grpc-encoding`), sends
  the messages uncompressed, half-closes, and records a normal gRPC exchange (`initiator`, `resentFrom`) with all
  response messages, status and trailers. Unary and server-streaming; client / bidi streaming send all messages then
  half-close (documented). ≤ 100 messages, ≤ 4 MB each, ≤ 16 MB total; deadline 60 s (`grpc-timeout: 60S`) unless the
  headers carry one.
- Host: `resend` of a gRPC exchange re-sends its recorded request messages (refused when one was truncated /
  `sizeUnknown`); edit & resend takes `messagesJson` (encoded with the request type) or base64. Agents:
  `resend_request` gains `grpc: {messagesJson? | messages?}`; `get_request` snippets stay HTTP-only (a `grpcurl`
  snippet is a later item).
- Webview: Resend / Edit & resend for gRPC rows (JSON editor per message when the schema decodes, base64 otherwise).

### 18.5 Security review items
Rewrite validation (reserved metadata, CR/LF, base64 `-bin`), script hooks bounded (time, size, message count per call),
map remote never bypasses the LAN SSRF guard or the client-certificate Origin rule, send caps and deadline, resend from
LAN-recorded exchanges only to the same targets the LAN guard allows, agents' `resend_request grpc` behind write access.

### 18.6 REVIEW-12 amendments
- **No relay loops.** Every relayed / sent gRPC call carries a per-instance hop marker the proxy strips upstream; a call
  arriving with our marker, or whose upstream target is one of the proxy's own listeners (loopback / emulator aliases /
  the LAN listener, any of its ports), is answered trailers-only `14` "Flutter Intercept: the call would loop back to the
  proxy" and recorded once. Map remote rules (shared, personal or agent) whose target is the proxy's own port are refused
  by validation.
- **`send()` for gRPC follows the rules like HTTP `send()`.** Block / fault / throttle / grpcMock / mapRemote / rewrite /
  breakpoints / mutate / scripts, the network profile and replay (incl. `fallback: fail`) apply to resent gRPC calls
  exactly as to the app's calls (the docs that said otherwise are corrected).
- Agents' view of `scriptLog` redacts base64 runs (≥ 16 chars) as `[base64 N bytes]`; `messagesJson` "[redacted]"

  to 1 h; `onGrpcStatus` message ≤ 1 KB; the hook-name check ignores comments; a resend whose original record is gone
  can't skip the LAN check (refused).

## 20. v0.14.0 — Apps with their own certificate (2026-10-15)

certificate from the traffic panel (VS Code and Android Studio) to see those requests. No settings.json editing, no

`LearnedPassthroughReason`, `Exchange.learnedPassthrough` (proxy `types.ts`), `Status.learnedPassthrough` and the

### 20.1 Learned passthrough for HTTP / HTTPS (proxy)
One map in the proxy, `host:port` → `{reason, until}`, for HTTP CONNECTs and gRPC silent tunnels alike (the 0.13 gRPC
pin map becomes part of it; `grpcPinnedHosts` / `clearGrpcPinnedHosts` stay as thin views over it). A CONNECT to a
learned `host:port` is tunnelled like a `tlsPassthrough` host (§14.2: `kind: 'tunnel'`, same LAN guards, upstream proxy
chaining, block / fault rules on the CONNECT), the tunnel exchange carries `learnedPassthrough` and a note. The app then
does TLS with the real server itself, with its own certificate and key; the proxy never sees or stores them.

Two reasons:
- **`client-certificate`** — the server asks for a client certificate the proxy doesn't have:
  - a TLS alert `certificate_required` (116) on the upstream connection → at once;
  - `handshake_failure` (40) / `bad_certificate` (42) → only once confirmed that the server asks for a client
    certificate (e.g. a short TLS 1.2 probe to the same `host:port`, through the upstream proxy if one is set, that sees
    a `CertificateRequest`; the probe sends no certificate and no application data, ≤ 5 s, at most one at a time per
    `host:port`, ≤ 4 at once). Not confirmed → no learning, the error stays as today;
  - an HTTP 400 whose body says `No required SSL certificate was sent` (nginx with `ssl_verify_client on`) → at once.
  Lasts until the proxy stops, the user forgets it, or a client certificate is configured for the host.
- **`pinned`** — the app rejects the proxy's certificate on a decrypted HTTPS CONNECT (the 0.13 rules for gRPC, now also
  for HTTP): a TLS alert from the app at once; a close / reset in the handshake twice within `PIN_STRIKE_WINDOW_MS`.
  Lasts `GRPC_PIN_TTL_MS` (10 min), as gRPC pins do. (Dio `validateCertificate` checks after the response, so the proxy
  can't see it: documented; `tlsPassthrough` is the answer there.)

Never learned:
- when a client certificate is configured for the host (§14.3): the configured certificate was presented and rejected →
  the exchange's error says `The server rejected the client certificate configured for <pattern> (<alert>).`;
- when an **enabled rule targets that host** (its URL pattern has a host part that matches the host, any action): the
  host stays decrypted so the rules keep working; the error says so and points to "Add client certificate…";
- while a recording is replayed; for hosts in `grpcDecryptHosts` (gRPC, as 0.13); for the proxy's own send/resend tunnel.
- Cap: 1000 entries (expired ones dropped first, then nothing new is learned).

Exchange text (exact wording, the agents and the panel show it as is):
- The request that failed (state `error`; the response the app gets is a 502 with `Connection: close`, or the server's
  own 400, also with `Connection: close`, so the app's next request opens a new CONNECT): `error` =
  `This server needs the app's own client certificate (<cause>). From now on <host> is passed through without decryption, so the app talks to it directly with its own certificate. To see these requests, add the certificate in the Flutter Intercept panel (Add client certificate…).`
  — and `learnedPassthrough` = `{reason: 'client-certificate', host, port}`. The proxy closes the app's other idle
  keep-alive connections to that `host:port` too.
- Tunnels passed through because of it: note `This server needs the app's own certificate: passed through without decryption.`
  (`pinned`: `<host> pins its certificate: passed through without decryption.`), plus `learnedPassthrough`.

API (`InterceptProxy`): `get learnedPassthrough(): LearnedPassthrough[]` (only live entries), `forgetLearnedPassthrough(
key?: string)` (`host:port`, none = all), event `'learnedPassthrough'` (the list) after every change.
`setClientCertificates()` drops `client-certificate` entries whose host now matches a loaded certificate.
`setGrpcDecryptAll(true)` keeps resetting only `pinned` entries learned from gRPC, as 0.13.

### 20.3 Adding a client certificate from the panel (host + webview; plugin: same messages)
Webview → host:
- `{type: 'chooseClientCertificateFile', role: 'pfx' | 'cert' | 'key'}` → the host's native file picker (filters:
  `.p12 .pfx` / `.pem .crt .cer` / `.pem .key`, any file allowed) → host → webview
  `{type: 'clientCertificateFile', role, file?: {token, name}, problem?}`. `token` = random, one use, valid 10 min, bound
  to this panel; `name` = the file's base name. **The path never reaches the webview.**
- `{type: 'addClientCertificate', host, pfx?: token, cert?: token, key?: token, passphrase?: string}` → host:
  checks the host pattern (`certHostProblem`), the tokens, loads the files with the §14.3 rules (absolute, regular file,
  ≤ 1 MB, non-blocking open), tries `tls.createSecureContext` with the passphrase; then writes the entry (paths) to the
  **user-level** `flutterIntercept.clientCertificates` (replaces an entry with the same host, case-insensitive; ≤
  `MAX_CLIENT_CERTS`), stores the passphrase in secret storage (`passphraseSecretKey(host)`; empty → deleted), reloads
  the certificates (which forgets the learned entry, §20.1). Answer `{type: 'clientCertificateSaved', host, problem?}`
  — a problem (wrong passphrase, key doesn't match…) keeps the popup open. The passphrase is never logged, echoed back,
  put in Status, or kept by the webview after sending.
- `{type: 'removeClientCertificate', host}` → removes the user-level entry with that host and its secret; Status updates.
- `{type: 'forgetLearnedPassthrough', host?, port?}` → `forgetLearnedPassthrough`.
- Controller: these go to `ControllerDeps.clientCertUi?: ClientCertUi` (`src/ui/clientCertUi.ts`; without it → `error`
  "Adding client certificates isn't available here."). One shared, vscode-free implementation
  (`createClientCertUi(platform)`) holds the tokens and the checks; each IDE gives a small `ClientCertPlatform`:
  `pickFile(role)`, `readEntries()` / `writeEntries(entries)` (user level), `setPassphrase(host, value | undefined)`.
  VS Code: `showOpenDialog`, `ConfigurationTarget.Global`, `context.secrets`. Plugin: sidecar → IDE ui-requests
  (`FileChooser`, `InterceptSettings` (application level), `PasswordSafe`).

Webview:
- A failed exchange or tunnel row with `learnedPassthrough.reason === 'client-certificate'`: a banner "This server needs
  the app's own certificate…" with **Add client certificate…** (host prefilled: `host`, plus `:port` when not 443) and
  **Try decrypting again** (forget). `pinned`: the banner without the add button.
- **Add client certificate** popup: host field; "Certificate file" choice: PKCS#12 (`.p12`/`.pfx`, one file) or PEM
  (certificate + private key); passphrase (password field, optional); Save / Cancel; problems inline. It explains, in
  plain words (owner's request):
  *Why*: "This server asks the app to prove who it is with a certificate (mutual TLS). Flutter Intercept sits between
  your app and the server, so to show you these requests it has to present the same certificate to the server.
  Without it, the requests still work but are passed through without decryption."
  *Stays on your computer*: "The certificate stays where it is on this computer: Flutter Intercept only remembers its
  location and reads it when connecting. It is never uploaded or sent anywhere except to this server during the TLS
  handshake, exactly as your app does. The passphrase is kept in VS Code's secret storage (Android Studio: the IDE's
  password safe)." (The plugin build says the Android Studio variant.)
- A small **Client certificates** list (from `Status.clientCertificates`: host, problem) with Remove (confirm inline)
  and **Add…** (empty host); and the learned hosts (`Status.learnedPassthrough`: host:port, reason, Forget).

### 20.5 As built (v0.14.0, after REVIEW-14 and PERF-2)
- **Key and destination.** Entries are keyed on the CONNECT target (the `host:port` the app's CONNECT named — what
  its next CONNECT is matched on). A refusal teaches only when the request names that same server: the URL host (Host,
  `:authority` or SNI) equals the CONNECT target's host and the port matches. A CONNECT to an IP whose Host / SNI /
  `:authority` names another host teaches nothing (the error stays as before); an app connecting by IP with Host = the
  IP is learned under the IP.
- **Per client.** `client-certificate` entries describe the server and apply to every client. `pinned` entries and
  pin strikes are per client: the peer address of its connection to the proxy (the LAN device's address in LAN mode;
  every loopback address is one client — local processes, iOS simulators and Android emulators can't be told apart).
  A pin passes only that client's CONNECTs and silent tunnels through. `learnedPassthrough` shows one entry per
  `host:port` (pins from several clients merged, latest `until`).
- **Strikes.** A TLS alert from the client pins at once, for that client. A close / reset in the handshake is a
  strike only once the proxy's TLS flight was written to that connection (> 512 bytes since the CONNECT); two strikes
  within `PIN_STRIKE_WINDOW_MS` pin. Not counted at all when that client completed a decrypted request to the same
  `host:port` within `PIN_STRIKE_WINDOW_MS`; a connection that carried a request ends its handshake watch.
- **Caps.** 1000 entries in all, 250 per teaching client (a client at its limit loses its own oldest entry). Full map:
  expired entries first, then the oldest pin; only a map full of `client-certificate` entries refuses a new one.
  Strikes ≤ 1000, swept by age.
- **Step-aside.** Both reasons step aside while a recording is replayed or an enabled rule names the host (also rules
  added later): the host is decrypted again meanwhile.
- **Event** `'learnedPassthrough'` also fires when a pin expires (one timer at the earliest `until`); not for an
  unchanged relearn.
- **nginx.** `Connection: close` is added at the head of an HTTPS 400 only when it is `text/html` and the host may be
  learned (no configured certificate, no rule naming it, no replay).
- **Probe.** Answers are reused both ways for `PROBE_NEGATIVE_MS`; a probe counts toward the 4-at-once cap until its
  work ends; through an upstream proxy its CONNECT has the same 5 s deadline.
- **Host.** `ClientCertPlatform` gained `getPassphrase?` (a failed save restores the old passphrase), `confirmRemove?`
  (IDE confirmation; cancel = nothing changes, nothing sent), `reload?`; `ClientCertUi.remove` returns
  `{cancelled?}`. One file chooser at a time. `flutterIntercept.clientCertificates` is `machine`-scoped (not synced).
- **Plugin.** Requests `ui.chooseClientCertificateFile`, `settings.writeClientCertificates`,
  `secrets.setClientCertPassphrase`, `secrets.clientCertPassphrase`, `ui.confirmRemoveClientCertificate`. Settings
  Apply merges the user's certificate-text edits onto what is stored now.

### 20.6 Native clients on the Android emulator (found by the devices suite)
While the host routes an emulator's native clients through the proxy (§14.7, `nativeClients: "proxy"`), HTTPS pin
learning is off: `InterceptProxy.setHttpPinLearning(false)` (on again when the last emulator is released; turning it
off forgets the HTTPS pins; gRPC pins unaffected). Native clients that don't trust the CA are expected there; the host
notices that in the HTTP profile and stops routing (§14.8), and the emulator's clients share the app's loopback client,
so a pin would also pass the Dart app's own requests to that host through. Wiring: `AndroidGlobalProxy`
`onRoutedChange(routed)` → `InterceptProxyHost.setHttpPinLearning(!routed)` (kept across proxy restarts), in the
extension and the sidecar.

### 20.7 Telling the developer what the server sees; turning automatic passthrough off (owner request, before release)
- **Setting** `flutterIntercept.autoPassthrough` (boolean, default `true`; any scope — turning it off only makes the
  proxy do less); sidecar `autoPassthrough`, plugin checkbox in Settings → Tools → Flutter Intercept ("Pass servers that
  need the app's own certificate, or that the app pins, through automatically"). Proxy: option
  `InterceptProxyOptions.autoPassthrough` (default true), `setAutoPassthrough(on)`, getter `autoPassthrough`; the host
  keeps it across restarts.
- **Off:** nothing is learned (neither reason, HTTP or gRPC — except 0.13's gRPC pins under decrypt-all, which keep
  working as before), **no probe** is sent, no `Connection: close` is added, idle connections aren't closed. Turning it
  off forgets every learned entry except those gRPC pins. The failed request's error then reads:
  `This server needs the app's own client certificate (<cause>). Automatic passthrough is off (flutterIntercept.autoPassthrough), so its requests keep failing through Flutter Intercept: add the certificate in the Flutter Intercept panel (Add client certificate…), or turn it on.`
  For alerts 40 / 42 (no probe): `The server ended the TLS handshake (<alert>); it may need the app's own client certificate. Automatic passthrough is off, so Flutter Intercept didn't check: add the certificate in the panel (Add client certificate…) if it needs one.`
- **`Exchange.needsClientCertificate?: {host, port}`** — set on the failed request whenever the proxy concluded the
  server wants a client certificate (learned or not, i.e. also when automatic passthrough is off or the host is kept
  decrypted by a rule / replay). The webview's banner offers **Add client certificate…** for it even without
  `learnedPassthrough` (no "Try decrypting again" then). Agents: `get_request` / `list_requests` show it; HAR
  `_needsClientCertificate`.
- **`Status.autoPassthrough`** (boolean). The panel's certificates list says "Automatic passthrough is off" when false;
  agents' `get_status` shows it.
- **Popup text** — a third section, *What the server sees* (owner's request, plain words):
  "The server gets the same certificate, but the connection now comes from Flutter Intercept instead of your app, and
  it looks a little different to the server. Most servers don't notice; some security systems do. Use a certificate
  you're allowed to use for testing, ideally with a development or staging server."
  And under the banner of a learned request (one line): "The first request was tried without the app's certificate,
  so the server may have logged one refused connection from this computer."
- **README** tutorial "Apps with their own certificate": a short *What the server sees* paragraph (the first refused
  attempt, at most one short check for unclear refusals, the different-looking connection after adding the
  certificate, nothing that names Flutter Intercept — internal headers are removed), and how to turn automatic
  passthrough off. Plugin README the same in two lines.
