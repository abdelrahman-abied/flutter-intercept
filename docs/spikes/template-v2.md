# Spike — template v2: keep interception when the app sets `findProxy` or pins certificates

Date 2026-10-08 · Flutter 3.47.6 / Dart 3.13.5 · Agent A (Phase 2)

## Verdict: **adopt v2.** The wrapper fixes both target limits and costs nothing

`createHttpClient` now returns `_InterceptedHttpClient`. It is a forwarding `HttpClient` that
ignores app assignments to `findProxy` and `badCertificateCallback` and prints one console
line per kind, e.g. `[flutter_intercept] ignored app findProxy (requests stay on the intercept proxy)`.

Measured on the Android emulator and the iOS simulator:

| Pattern | v1 (current CONTRACTS §1) | v2 |
|---|---|---|
| Charles snippet `findProxy = (u) => 'PROXY 127.0.0.1:8888'` | ❌ requests **fail** (connection refused) | ✅ intercepted |
| `findProxy = HttpClient.findProxyFromEnvironment` | ❌ silently **DIRECT** (not intercepted) | ✅ intercepted |
| Pinning with `badCertificateCallback` | ❌ silently **DIRECT**: the pinned TLS handshake fails, and the `; DIRECT` fallback goes to the real server | ✅ intercepted |
| Pinning with `SecurityContext(withTrustedRoots: false)` | ✅ intercepted. Our callback **is** called, so this was never a problem | ✅ intercepted |
| Pinning with Dio `validateCertificate` (Dio's documented hook) | ❌ `DioException [bad certificate]` | ❌ same: **residual limit**, see below |

v2 compiles and passes the full harness on Dart **3.0.0, 3.3.0, 3.6.0, 3.9.0 and 3.13.5**, at
language versions **2.12 and 3.0** each (real SDKs, see Compatibility). It also passes as an
AOT executable at language 3.13. Every Phase 1 device check still passes on both
platforms, including profile, the flavor target, the app's own `HttpOverrides.global`,
hot restart and the `; DIRECT` fallback.

## Proposed template (CONTRACTS §1 replacement)

The placeholders and generator rules are unchanged: only `TARGET_IMPORT`, `PROXY_HOST` and
`PROXY_PORT` are filled, plus the `FLUTTER_INTERCEPT_ENTRY_SHA` define. The source of truth is
`scripts/e2e/templates/entry_v2.dart.tmpl`, which `scripts/e2e/gen_entry.sh` renders.

```dart
// GENERATED by Flutter Intercept. Do not edit. Safe to delete.
import 'dart:async';
import 'dart:io';
import '{{TARGET_IMPORT}}' as target; // package:<app>/<path> when under lib/, else relative

const _proxy = 'PROXY {{PROXY_HOST}}:{{PROXY_PORT}}; DIRECT';

String _findProxy(Uri url) => _proxy;
bool _acceptCertificate(X509Certificate cert, String host, int port) => true;

final Set<String> _noted = <String>{};
void _note(String message) {
  if (_noted.add(message)) print('[flutter_intercept] $message');
}

class _FlutterInterceptOverrides extends HttpOverrides {
  _FlutterInterceptOverrides(this._previous);
  final HttpOverrides? _previous;
  bool _creating = false;

  @override
  HttpClient createHttpClient(SecurityContext? context) {
    // Re-entered from a delegate that calls HttpClient() itself: give it a
    // plain client; the outer call configures and wraps it.
    if (_creating) return super.createHttpClient(context);
    // Our zone value shadows any HttpOverrides.global the app installs later;
    // delegate to it so the app's own overrides still apply underneath ours.
    final global = Zone.root.run(() => HttpOverrides.current);
    final delegate = (global != null && !identical(global, this)) ? global : _previous;
    HttpClient client;
    if (delegate != null) {
      _creating = true;
      try {
        client = delegate.createHttpClient(context);
      } finally {
        _creating = false;
      }
    } else {
      client = super.createHttpClient(context);
    }
    if (client is _InterceptedHttpClient) return client;
    client
      ..findProxy = _findProxy
      ..badCertificateCallback = _acceptCertificate;
    return _InterceptedHttpClient(client);
  }
}

/// Forwards every member to the real client, except that app assignments to
/// `findProxy` and `badCertificateCallback` made after creation (Charles-style
/// snippets, certificate pinning) are ignored so traffic stays interceptable.
/// Callback setters take `dynamic` so their exact function types can never
/// mismatch the SDK; members added by future SDKs reach `noSuchMethod`.
class _InterceptedHttpClient implements HttpClient {
  _InterceptedHttpClient(this._client);
  final HttpClient _client;

  @override
  set findProxy(dynamic f) {
    if (f != null) _note('ignored app findProxy (requests stay on the intercept proxy)');
  }

  @override
  set badCertificateCallback(dynamic callback) {
    if (callback != null) {
      _note('ignored app badCertificateCallback (certificate checks are relaxed while intercepting)');
    }
  }

  @override
  set connectionFactory(dynamic f) {
    if (f != null) _note('app set connectionFactory: its connections may bypass the intercept proxy');
    _client.connectionFactory = f;
  }

  @override
  Duration get idleTimeout => _client.idleTimeout;
  @override
  set idleTimeout(Duration value) => _client.idleTimeout = value;
  @override
  Duration? get connectionTimeout => _client.connectionTimeout;
  @override
  set connectionTimeout(Duration? value) => _client.connectionTimeout = value;
  @override
  int? get maxConnectionsPerHost => _client.maxConnectionsPerHost;
  @override
  set maxConnectionsPerHost(int? value) => _client.maxConnectionsPerHost = value;
  @override
  bool get autoUncompress => _client.autoUncompress;
  @override
  set autoUncompress(bool value) => _client.autoUncompress = value;
  @override
  String? get userAgent => _client.userAgent;
  @override
  set userAgent(String? value) => _client.userAgent = value;

  @override
  Future<HttpClientRequest> open(String method, String host, int port, String path) =>
      _client.open(method, host, port, path);
  @override
  Future<HttpClientRequest> openUrl(String method, Uri url) => _client.openUrl(method, url);
  @override
  Future<HttpClientRequest> get(String host, int port, String path) => _client.get(host, port, path);
  @override
  Future<HttpClientRequest> getUrl(Uri url) => _client.getUrl(url);
  @override
  Future<HttpClientRequest> post(String host, int port, String path) => _client.post(host, port, path);
  @override
  Future<HttpClientRequest> postUrl(Uri url) => _client.postUrl(url);
  @override
  Future<HttpClientRequest> put(String host, int port, String path) => _client.put(host, port, path);
  @override
  Future<HttpClientRequest> putUrl(Uri url) => _client.putUrl(url);
  @override
  Future<HttpClientRequest> delete(String host, int port, String path) =>
      _client.delete(host, port, path);
  @override
  Future<HttpClientRequest> deleteUrl(Uri url) => _client.deleteUrl(url);
  @override
  Future<HttpClientRequest> patch(String host, int port, String path) =>
      _client.patch(host, port, path);
  @override
  Future<HttpClientRequest> patchUrl(Uri url) => _client.patchUrl(url);
  @override
  Future<HttpClientRequest> head(String host, int port, String path) => _client.head(host, port, path);
  @override
  Future<HttpClientRequest> headUrl(Uri url) => _client.headUrl(url);

  @override
  set authenticate(dynamic f) => _client.authenticate = f;
  @override
  void addCredentials(Uri url, String realm, HttpClientCredentials credentials) =>
      _client.addCredentials(url, realm, credentials);
  @override
  set authenticateProxy(dynamic f) => _client.authenticateProxy = f;
  @override
  void addProxyCredentials(String host, int port, String realm, HttpClientCredentials credentials) =>
      _client.addProxyCredentials(host, port, realm, credentials);
  @override
  set keyLog(dynamic callback) => _client.keyLog = callback;
  @override
  void close({bool force = false}) => _client.close(force: force);

  // Only reached for HttpClient members added by a future SDK (all members of
  // Dart 3.0-3.13 are forwarded above). Setters are dropped (the app keeps
  // working with the SDK default); getters/methods cannot be forwarded.
  @override
  dynamic noSuchMethod(Invocation invocation) {
    _note('HttpClient member ${invocation.memberName} is not supported by this Flutter Intercept version'
        '${invocation.isSetter ? ' (assignment ignored)' : ''}');
    if (invocation.isSetter) return null;
    return super.noSuchMethod(invocation);
  }
}

Future<void> main(List<String> args) async {
  final overrides = _FlutterInterceptOverrides(HttpOverrides.current);
  HttpOverrides.global = overrides;
  // Zone value wins over a later `HttpOverrides.global = ...` inside the app.
  await HttpOverrides.runWithHttpOverrides(() async {
    // Works for `void main()`, `Future<void> main() async` and `main(List<String>)`.
    final dynamic entry = target.main;
    final dynamic result = entry is Function(List<String>) ? entry(args) : entry();
    if (result is Future) await result;
  }, overrides);
}
```

Changes from v1:
- **Wrapper**: `createHttpClient` configures the real client, then returns `_InterceptedHttpClient(client)`.
- **Reentry**: `if (_creating) return super.createHttpClient(context);` moved to the top.
  A delegate that calls `HttpClient()` itself now gets a plain client, and the outer call
  wraps it exactly once. `if (client is _InterceptedHttpClient) return client;` guards
  against double wrapping.
- **Shared helpers**: `_findProxy` / `_acceptCertificate` are top-level functions, and
  `_note` prints at most once per message per isolate. Hot restart resets it, so the
  note shows once per run.
- `(_, __, ___)` is gone: the callbacks are named functions, so there is no lint noise.

## Compatibility analysis

**What was verified (real SDKs, downloaded official `dartsdk-macos-arm64` zips)**

`scripts/e2e/compat/run_compat.sh <sdk>...` generates the entry for a dart:io-only harness
(`scripts/e2e/compat/lib/app.dart`, written in 2.12 syntax) and runs it through the test
proxy. It covers plain, Charles `findProxy`, env `findProxy`, `badCertificateCallback` pin,
`SecurityContext` pin, the forwarded fields (idleTimeout, connectionTimeout,
maxConnectionsPerHost, autoUncompress and userAgent, all read back and seen upstream),
`postUrl/putUrl/patchUrl/deleteUrl/headUrl/get`, the callback setters (authenticate,
authenticateProxy, keyLog, connectionFactory, addCredentials, addProxyCredentials),
`close(force: true)` then use (`StateError`), and an app global override kept.

```
dart 3.0.0  lang 2.12 / 3.0 : COMPAT_DONE failures=0   (both)
dart 3.3.0  lang 2.12 / 3.0 : failures=0
dart 3.6.0  lang 2.12 / 3.0 : failures=0
dart 3.9.0  lang 2.12 / 3.0 : failures=0
dart 3.13.5 lang 2.12 / 3.0 : failures=0
dart 3.13.5 lang 3.13, `dart compile exe` (AOT) : failures=0
v1 baseline on 3.13.5: failures=3 (charles_findProxy refused, env_findProxy DIRECT, pin_badCertificateCallback DIRECT)
```

- The `HttpClient` member list (fields, methods, setters) is **textually identical** in
  3.0.0, 3.3.0, 3.6.0, 3.9.0 and 3.13.5: 29 members, and it is
  `abstract interface class HttpClient` in all of them, so implementing it is allowed.
  `connectionFactory` and `keyLog` predate 3.0.
- **The explicit list is complete**: with `noSuchMethod` removed, `dart analyze` reports
  `No issues found!` on 3.0.0 and 3.13.5. Positive control: also removing `set keyLog` gives
  `Missing concrete implementation of 'setter HttpClient.keyLog'`.
- Flutter 3.10 shipped Dart 3.0, so this covers every Flutter release with Dart 3.

**How the template stays compile-safe**
- Getters use exact types (`Duration`, `Duration?`, `int?`, `bool`, `String?`). These have
  been stable since null safety and are the only signatures that must match exactly.
- Callback setters take `dynamic`. A wider parameter type is always a valid override, so
  any future change to a callback's function type still compiles.
- `@override` on a member the SDK lacks is only an analyzer warning, never a compile error.
- Methods (`open…headUrl`, `addCredentials`, `addProxyCredentials`, `close`) are spelled out
  in signatures unchanged since Dart 1/2. *Inferred risk:* a future SDK adding an optional
  parameter to one of them would make the override invalid and break compilation. Dart
  treats such interface changes as breaking (they break every implementer), so it is
  unlikely and would be announced.

**When a future SDK adds a member (inferred + simulated)**
- Compilation still works: the class declares `noSuchMethod`, so the compiler generates
  forwarders for any member we don't declare.
- At runtime a new **setter** is dropped with a note, so the app keeps the SDK default.
  Simulated by deleting `set keyLog`: `[flutter_intercept] HttpClient member
  Symbol("keyLog=") is not supported by this Flutter Intercept version (assignment
  ignored)`, and the request was still intercepted.
- A new **getter or method** throws `NoSuchMethodError` after the note, only if something
  calls it. It cannot be forwarded because Flutter has no `dart:mirrors`.
- Recommended guard for the extension's CI: run the "strict" check above (the wrapper
  without `noSuchMethod`, `dart analyze`) against each new stable SDK. A new member shows
  up as a missing-implementation error before users hit it.

**Language version.** The entry inherits the app's version, possibly 2.12. The template
uses no records, patterns, class modifiers or `_` wildcards. Verified at 2.12 on every SDK
above.

## Does the wrapper break anything?

| Consumer | Result |
|---|---|
| Dio `IOHttpClientAdapter` (default and `createHttpClient:`) | ✅ device runs. Dio's `connectionTimeout` writes and `close` are forwarded. `validateCertificate` still runs on the proxy's certificate (see limits) |
| package:http `IOClient(HttpClient)` and top-level `http.get` | ✅ device runs (IOClient closes with `close(force: true)`, forwarded) |
| `HttpClient.close` / use after close | ✅ `close(force: true)` then `getUrl` → `StateError` (same as unwrapped) |
| Connection reuse | ✅ unchanged: 5 sequential GETs on one client gave `CONNECT=5 REQ=5` with **both** v1 and v2. The pool lives in the inner `_HttpClient`, and the wrapper holds no connection state |
| App `HttpOverrides.global` | ✅ still delegated, UA tag kept (device + VM) |
| `connectionFactory` set by the app | forwarded, with note `app set connectionFactory: its connections may bypass the intercept proxy`. Dart passes the proxy host/port to the factory, so a factory that uses them stays intercepted (VM case passes). One that ignores them bypasses us |
| `WebSocket.connect` | not exercised; it uses `openUrl` + `detachSocket` on the returned request, which the wrapper doesn't touch |
| `compute()` / background isolates | out of scope and unchanged: overrides are per isolate, so clients there are direct and the app's findProxy/pinning apply |
| `runtimeType` / `is _HttpClient` checks | `runtimeType` is now `_InterceptedHttpClient`. No dart:io or package code relies on it |

## Residual limits

1. **Dio `validateCertificate` pinning** (Dio README's recommended pinning: `sha256(cert.der) == pin`).
   Dio checks `response.certificate` after the request, so the app sees the proxy's leaf.
   Outcome: Dio requests fail with `DioException [bad certificate]` while intercepting, and
   work with the proxy off. Two options for a later phase:
   - **(a) No MITM for selected hosts.** A proxy rule tunnels the CONNECT without
     terminating TLS (Agent C / mockttp). The app works but those hosts are opaque.
   - **(b) Relay the real certificate.** The proxy sends the upstream leaf DER in a
     private header. The wrapper also wraps `HttpClientRequest`/`HttpClientResponse` and
     returns an `X509Certificate` implementation built from it (the interface can be
     implemented). The sha1/subject/issuer/validity fields would come from the proxy too.
     This is much more surface (≈45 forwarded members plus a header channel), so it is
     not proposed now.
2. The app wraps its code in its **own `HttpOverrides` zone**: unchanged from Phase 1, not intercepted.
3. **mTLS** (client certificate in the app's `SecurityContext`): the proxy cannot present the
   client certificate upstream, so the server rejects it. Not testable with the demo hosts.
4. **Native stacks** (cupertino_http, cronet_http, native_dio_adapter), **Flutter web**,
   and other isolates: unchanged known limits.
5. **Pinning is bypassed while intercepting.** This is intended for a debug tool, and the
   console note makes it visible. The extension should say so in the panel/README.
6. Not verified: release builds with `--obfuscate` (only noSuchMethod's note text uses
   `memberName`; nothing depends on it), and physical devices.

## Requested contract changes

1. **CONTRACTS §1**: replace the template with the one above. Generator rules are unchanged.
2. **PLAN Known limits**: remove "apps that pin certs by reassigning `badCertificateCallback`".
   Add "Dio `validateCertificate` pinning (fails while intercepting)", "mTLS client certs",
   and "an app `connectionFactory` that ignores the proxy host".
3. **Extension CI** (optional): the strict wrapper check per new Dart stable (above).
