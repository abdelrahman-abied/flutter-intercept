# Headless / CI mode — spike and as built (CONTRACTS §13.9)

Question: can `flutter test <generated entry that imports integration_test/x_test.dart and calls its main> -d
<device>` run integration tests through the proxy on macOS desktop, the Android emulator and an iOS simulator?
Measured 2026-10-10 with Flutter 3.47.6 (stable), Dart 3.13, on an Apple-silicon Mac: macOS desktop, Android
emulator `emulator-5554` (sdk gphone64 arm64), iPhone 17 simulator (iOS 27.0). App: a copy of `samples/demo_app` with
`integration_test: {sdk: flutter}` added to `dev_dependencies` and `integration_test/app_test.dart` (two
`testWidgets`: a `dart:io` `HttpClient` GET and a `package:http` GET to jsonplaceholder.typicode.com, both HTTPS).

## Verdict

**Works on all three, with a one-line wrapper under `integration_test/`.** The generated entry as is cannot be
passed to `flutter test`, for two independent reasons:

1. **Path.** flutter_tools decides "integration test (on a device)" vs "widget test (on the host)" by a string
   prefix: `absolutePath.startsWith('<cwd>/integration_test')` (`_shouldRunAsIntegrationTests`,
   `packages/flutter_tools/lib/src/commands/test.dart`). The entry at
   `.dart_tool/flutter_intercept/entry_integration_test__app_test.dart` was compiled as a host widget test with the
   `flutter_tester` listener; `-d macos` was silently ignored.
2. **`main` signature.** Both test listeners call `await Future(test.main)`, i.e. `main` must be callable with no
   arguments. The template's `Future<void> main(List<String> args)` fails to compile:
   `listener.dart:21:21: Error: The argument type 'Future<void> Function(List<String>)' can't be assigned to the
   parameter type 'FutureOr<dynamic> Function()'.`

The fix that needs no template change: the CLI writes, per entry,
`integration_test/.flutter_intercept/<entry name>_fi.dart`:

```dart
// GENERATED by Flutter Intercept (headless run). Do not edit. Deleted after the run; safe to delete.
import '../../.dart_tool/flutter_intercept/entry_integration_test__app_test.dart' as entry;

// flutter test calls main() without arguments.
Future<void> main() async => entry.main(const <String>[]);
```

and runs `flutter test integration_test/.flutter_intercept/<…>_fi.dart -d <device>
--dart-define=FLUTTER_INTERCEPT_PROXY=<host>:<port> --dart-define=FLUTTER_INTERCEPT_ENTRY_SHA=<sha>` from the
project root. The entry is the unchanged editor entry (same template, same `.dart_tool` path), which imports the
test file relatively and calls its `main`. The wrapper's name does not end in `_test.dart`, so a plain
`flutter test integration_test` never discovers it (directory discovery only takes `*_test.dart`, explicit paths
take any name — measured); the directory is hidden, gets a `.gitignore` with `*`, and is deleted after the run.
`flutter drive` was not needed.

| Device | `PROXY_HOST` | Build + run | Result | Exchanges through the proxy |
|---|---|---|---|---|
| macOS desktop (`-d macos`) | `localhost` | not timed (incremental build) | `All tests passed!` | 2 (HTTPS GET todos/1, users/1; 200, MITM'd with the run CA) |
| Android emulator (`emulator-5554`) | `10.0.2.2` | 41.6 s (Gradle 33.8 s) | `All tests passed!` | 2 |
| iOS simulator (iPhone 17, iOS 27.0, by UDID) | `localhost` | 63.8 s (Xcode build 28.9 s) | `All tests passed!` | 2 |
| entry passed directly (`.dart_tool/…`) | — | — | compile error (above), run as a host test | 0 |

Notes from the runs:
- Integration tests run the test bodies in the test framework's zone, not inside the entry's
  `runWithHttpOverrides` zone, so interception comes from the entry's `HttpOverrides.global` (also set). Both
  requests (plain `HttpClient` and `package:http`'s `IOClient`) were intercepted. Request→source chains (§9.1) are
  less precise in tests for the same reason (not needed headless).
- `integration_test` must be a dev dependency of the app (flutter refuses otherwise: "cannot run without a
  dependency on package:integration_test"). Any project that already has integration tests has it.
- macOS prints `Failed to foreground app; open returned 1` when run without a GUI session in front; harmless.
- Several targets → several wrappers in one `flutter test` call; `FLUTTER_INTERCEPT_ENTRY_SHA` is then the first 12
  hex of sha1 of the entries' shas (one entry: its own sha, as in §1).

## As built (`packages/cli`)

`flutter-intercept test|run [targets…] [options] [-- flutter args]`; `node packages/cli/dist/cli.js` (esbuild
bundle, shebang, 1.7 MB, no `vscode`).

- **Reused from packages/extension/src (all vscode-free, checked by bundling):** `entry/generator.ts` (planEntry /
  writeEntry / PROXY_DEFINE), `ca.ts` (loadOrCreateCa into a temp dir), `rules/core.ts` `SharedRulesCore` (parsing,
  validation via `ui/controller.ts` `validateRule`, body and script file checks, approval reasons; in-memory approval
  store, never writes), `recordings/{store,replay,validate}.ts`, `agent/har.ts` `buildHar`, `adb.ts`
  `ReverseTracker`, `agent/redact.ts`, and **`agent/api.ts` `AgentApi` itself for `--assert`** (constructed over the
  finished exchanges with a stub host; `call('assert_traffic', input)` — same zod validation, matching, redaction
  and failure texts as the agent tool). Not copied: nothing. `rules/service.ts` imports vscode, so the CLI has its
  own read-only `RulesFs` (6 lines).
- **Run CA:** `mkdtemp(<tmp>/flutter-intercept-run-*)`, chmod 0700, CA file 0600 (ca.ts), deleted in `finally`.
  Never trusted system-wide; only the generated entry trusts it.
- **Proxy:** `InterceptProxy({port: --port ?? 0, host: '127.0.0.1', ca, maxExchanges: 20000})`.
- **Devices** (`flutter devices --machine` unless the id says it: `macos`/`linux`/`windows`, `emulator-*`):
  `emulator-*` → `10.0.2.2`; other Android (physical, Genymotion…) → `localhost` + `adb reverse` (removed after,
  user-managed reverses untouched); iOS simulator / desktop → `localhost`; physical iOS and web → refused (exit 2).
  No `-d`: the only connected non-web device, else "pass --device".
- **Shared rules:** default `.vscode/flutter-intercept.json` in the project or the nearest folder above it with one
  (stops at the git root). Rules needing approval (non-loopback map remote, request header rewrites, every `script`,
  …: `policy.ts` reasons) are skipped with `rules: skipped (needs approval; pass --approve-shared-rules to apply):
  Rule "…" (…): <reason>`; `--approve-shared-rules` applies them and prints what it approved. A `--rules` file
  elsewhere must be inside the git repository (or the project); body / script files resolve against that root.
  `breakpoint` rules are turned off (nobody can resume headless) with a problem line.
- **Replay** (`--replay <id|name|file>`, `--replay-fallback`), **network profile** (`offline`, `slow-3g`,
  `fast-3g`, `flaky`), **`--har`** (redacted unless `--no-redact`; 0600 when not redacted), **`--record`** (a name →
  the project's recordings via the store; a path → saved through the store, exported, project copy removed;
  unredacted like the editor default), **`--assert`** (JSON array of `assert_traffic` inputs, optional `name`,
  `withinMs` forced to 0 with a note, validated before the build), **`--junit`**.
- **flutter:** `--flutter`, else `$FLUTTER_ROOT/bin/flutter`, else `flutter` on PATH; inherited stdio; cwd = project
  root; the user's `--dart-define=FLUTTER_INTERCEPT_*` after `--` are dropped (ours win).
- **Exit code:** flutter's when non-zero; else 1 if an assertion failed; else 0. Usage / setup errors 2 (nothing ran),
  interrupted `test` 128+signal (130 / 143). `run` exits 0/1 after Ctrl-C (the normal way to stop it).
- **Ctrl-C / SIGTERM:** first signal: wait 2 s for flutter (a terminal Ctrl-C already reached it), then forward the
  signal, SIGKILL after 10 s more; second signal: SIGKILL now. Then outputs, summary, cleanup (wrappers, adb
  reverse, proxy, CA dir). Measured: SIGTERM during the macOS build → flutter stopped ("No tests ran"), exit 143,
  wrapper dir and temp CA dir gone, no flutter_tools process left.
- **Summary** (stdout): traffic grouped by method + URL without query (count, statuses, `*` = answered by a rule /
  replay, slowest), the assertion table with failure texts, exit codes. Progress lines go to stderr.

Real runs through the CLI (copy of the demo with the dev dependency): macOS, Android emulator, iPhone 17 simulator —
shared mock applied, map remote skipped for approval, 3/3 assertions passed, HAR / JUnit / recording written; replay
of that recording with `--replay-fallback fail --network-profile fast-3g` on the emulator (2 replayed); a failing
expectation → exit 1 with flutter's tests passing. `packages/cli/test/e2e.sh macos emulator-5554` passes.

## REVIEW-7 fixes (#10–#13)

- **#10:** printed commands (`flutter test …` log, `run`'s `flutter run …` lines) show `--dart-define=NAME=***` for
  every user define (`--dart-define=`, `--dart-define NAME=…`, `-D…`), ours in full; other arguments go through
  `redactText`. flutter still gets the real values. (`src/command.ts`)
- **#11:** no `shell: true` anywhere. `flutter.bat` / `.cmd` runs as `cmd.exe /d /s /c "<line>"` with
  `windowsVerbatimArguments`, every argument quoted and caret-escaped twice (cross-spawn's rules), the path escaped
  once, line breaks refused; anything else is spawned directly. Same for `flutter devices --machine`. Tests simulate
  cmd.exe's two parsing passes and argv splitting: `&`, `|`, `<>`, `%VAR%`, quotes, spaces, trailing backslash and
  empty arguments come back unchanged (not run on a Windows machine).
- **#12:** the default rules search walks up only inside a git work tree (to its root); outside one only
  `<project>/.vscode/flutter-intercept.json`. A rules file (default or `--rules`) is refused (exit 2) when it or a folder
  between it and its workspace folder is world-writable, or — unless we run as root (CI containers) — owned by a user
  other than us or root. POSIX only.
- **#13:** outputs are written to a random `wx` temp name and renamed (a planted link at the target is replaced, not
  followed); the wrapper folder and `.dart_tool/flutter_intercept` go through `ensureDirInside` (har.ts: no symlinked
  component, created one level at a time); wrappers / `.gitignore` are removed and recreated with `wx`; a symlinked
  entry file is unlinked before `writeEntry`. SIGHUP is handled like SIGTERM (flutter gets SIGTERM; exit 129), and a
  `process.on('exit')` hook removes the wrappers, the temp CA dir and the adb reverse (synchronously) if the run ends
  without its `finally`; `main` turns an uncaught exception into `process.exit(2)` so the hook runs.

## v0.8.0 (CONTRACTS §14.1): GitHub Action, physical iPhones, npm-ready package

### GitHub Action (root `action.yml`)

Composite action, `uses: abdelrahman-abied/flutter-intercept@v0.8.0`.

- **Build step** (`working-directory: ${{ github.action_path }}`): skipped when `packages/cli/dist/cli.js` and
  `dist/action.js` already exist (self-hosted runners keep action folders); else checks Node ≥ 18 on PATH, then
  `npm ci --no-audit --no-fund --ignore-scripts`, `npm run build --workspace packages/proxy`, `npm run build
  --workspace packages/cli`. Measured from a clean copy of the repository: 534 packages, 255 MB, about 5 s with a warm
  npm cache. `--workspace` filters on `npm ci` did not reduce the install (534 against 536 packages), so they're
  left out. `--ignore-scripts` is fine: esbuild finds its platform binary through its optional dependency.
- **Run step** (`id: run`, `working-directory: ${{ inputs.working-directory }}`): every CLI input reaches the
  process as `FI_INPUT_<NAME>`; no `${{ }}` inside any script (a unit test checks this). `exec node
  "$GITHUB_ACTION_PATH/packages/cli/dist/action.js"`: `src/action.ts` (bundled separately, 18 KB) builds the argv
  (`--name=value`, so a value that starts with `-` stays a value; list inputs: one per line, or space-separated on one
  line; `rules: none` → `--no-rules`; strict booleans; targets that look like options refused), writes
  `artifacts` / `har` / `junit` / `record` to `$GITHUB_OUTPUT` (random heredoc delimiter) before running, then
  `require('./cli.js').main(argv)` **in the same process**: the CLI's own SIGINT / SIGTERM / exit-hook cleanup apply
  with no signal forwarding, and the runner's cancel signal reaches it directly. `exit-code` is written after. Input
  errors → `::error::` (workflow-command data escaped) and exit 2.
- **Upload step**: `actions/upload-artifact@v7` (current major, checked 2026-10-10), `if: always() &&
  inputs.upload-artifacts == 'true' && steps.run.outputs.artifacts != ''`, `if-no-files-found: ignore`,
  `include-hidden-files: true`. Uploads the HAR (redacted), the JUnit report, and the recording only when `record`
  is a `.json` path (it is unredacted, and the user chose to write it).
- Extra inputs beyond the contract: `replay-fallback`, `artifact-name` (v4+ artifact names must be unique per run:
  matrix jobs set it), `upload-artifacts`. No `no-redact` input on purpose (uploaded HARs stay redacted).
- Outputs: `exit-code`, `har`, `junit`, `record`.
- Tests: `test/action.test.ts` parses action.yml with a dependency-free YAML subset parser (`test/yaml-subset.ts`;
  anything outside the subset throws) and checks the inputs against §14.1 and `CLI_INPUTS`, the env mapping, no
  expressions in scripts, `shell: bash`, the build order, the pinned upload action and its `always()`, that every
  `inputs.*` / `steps.*` reference exists and outputs map to what action.js writes, and that the README's workflow

### Physical iPhones (`test -d <udid>`)

- Detection: `flutter devices --machine`, `targetPlatform: ios` and `emulator: false` → `ios-physical` →
  `proxyRouteFor` returns `{ lan: true }` (it used to refuse).
- Before anything starts: `lanAddressForIphone()` (packages/extension/src/lanAddress.ts, vscode-free: default-route
  interface, VPN tunnels skipped, RFC 1918 only). None → exit 2 "this machine has no LAN address …"; a non-private
  address → exit 2 with the reason. `run -d <iPhone>` → exit 2 (it would have to print the token).
- After the loopback proxy starts: `proxy.openLan({host, token})` with a new 32-byte base64url token per run
  (`crypto.randomBytes`), define `FLUTTER_INTERCEPT_PROXY=flutter-intercept:<token>@<ip>:<lanPort>`
  (`lanProxyAddress` from `debug/rewrite.ts`). The proxy's LAN gate does the rest (§7): exact bind, constant-time
  `Proxy-Authorization`, the first authenticated peer pinned (logged: "iPhone connected from …"), SSRF guard.
- `closeLan()` in `finally` (before `stop()`); process exit closes the socket anyway.
- The token is never printed: `maskArgs` shows our defines with `user:***@` (`maskProxyCredentials`); `-v` /
  `--verbose` in the flutter args prints a warning (flutter's verbose build output contains define values). As
  defence in depth, `Proxy-Authorization` request headers are dropped from the exchanges before the HAR / recording
  / assertions (measured: the proxy does not record them today; the test checks the token and its base64 form are in
  neither the unredacted HAR nor the recording).
- The Local Network / firewall notes are printed once per run (`LAN_NOTES`).
- Tests (`test/run.test.ts`, `test/lan.test.ts`): refusal without / with a non-private LAN address before anything
  starts; `run` refused; with this machine's real LAN IPv4 (skipped when it has none): the define's form, 407 without
  and with a wrong token, the mock answered with the right one, token absent from every log line and both output files,
  notes printed once, the listener closed after the run (ECONNREFUSED).
- **Pending: verification on a real iPhone** (none was connected): signing, the Local Network prompt on first run,
  and the macOS firewall prompt for `node` are expected to behave as in the editor's LAN mode, but are unmeasured
  headless. A security review item (§14.1).
